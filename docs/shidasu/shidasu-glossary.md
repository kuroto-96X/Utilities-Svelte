# 星詠みソリティア -Shidasu- 用語集

`src/lib/game/shidasu/{engine,types,params,deck,items,rites,revelations,oracles,shop}.ts` の実装・コメントを元にした、Shidasuで使われる用語の定義集。ルールの詳しい計算式・数値は `docs/shidasu/shidasu-current-rules.md`(現行仕様書)を参照。本ドキュメントは「何と呼ぶか」「何を指すか」の整理に特化する。

各項目は「**日本語用語**(コード上の識別子) — 定義」の形式で記載する。コード上の識別子が存在しない(UI表示専用・概念のみの)用語は識別子欄を省略する。

## 1. 進行構造

- **ラン**(`RunState`, 1周) — タイトルからスタートし、8ステージ×各3ウェーブ=計24ウェーブを順にクリアしていく一連のプレイ全体。最終ステージのボスウェーブクリアで「全ステージクリア(allClear)」となる。
- **ステージ**(`stageIndex`) — ラン内に8つ存在する区切り。ステージが進むほど目標スコアの倍率(`stageTargetMultiplier`)が指数的に上昇する。
- **ウェーブ**(`WaveState`, `waveIndex`) — 山を1組配り直してから、目標スコア到達・全消し・手詰まりのいずれかで終了するまでの1回のプレイ単位。1ステージにつき3ウェーブ(`waveSlot` 1〜3)存在する。
- **フェーズ**(`RunPhase`) — ラン全体の現在の状態。`title`(タイトル画面)→`playing`(プレイ中)→`shop`(ショップ)/`itemSelect`・`riteSelect`・`revelationSelect`・`oracleSelect`・`cardSetSelect`(各アイテムの選択画面)/`continueChoice`(最終ステージのボスウェーブクリア時のみ)/`allClear`(全クリア)/`gameOver`(目標未達)を遷移する。
- **星**(`Star`) — ウェーブごとに割り当てられる、目標スコア倍率・報酬・制限/妨害内容を持つ要素。`waveSlot`(1〜3)ごとに専用の候補群があり、waveSlot3のみ必ず何らかの制限を伴う。ステージ突入時にステージ内3ウェーブ分がまとめて確定する。
- **ステージ制約**(`StageModifier`) — 星の制限内容から導出される、取得可否そのものに影響する特別ルール。`none`(制約なし)・`noLoop`(A⇔Kループ禁止)・`faceLock`(絵札はコンボ2以上でのみ取得可)の3種類。
- **得点ロック**(`BossScoreLock`) — 星の制限内容から導出される、取得はできるが条件を満たすと獲得点が0になる特別ルール(コンボ上限・奇数コンボ・特定スート・絵札など)。

## 2. 盤面要素

- **場札**(`tableau: Card[][]`) — 列ごとに積まれた、まだ取っていないカードの山。列数(既定7列)×実配布行数(既定5段+暗雲・虚による恒久加算分)で初期配布される。各列の一番手前(配列の末尾)のカードだけが取得対象になる。
- **山札**(`stock: Card[]`) — 場札配布後に残る、めくって使う予備の札。
- **基準カード**(`foundation`) — 場札から取得可能かどうかを判定する際の比較対象になる、直前に取得/めくったカード。取得したカードが新しい基準カードになる。
- **チェーン**(`chain: Card[]`) — 現在のコンボで取得/めくった順に並んだカードの履歴。コンボがリセットされると空になる(直後の1枚から再スタート)。
- **コンボ**(`combo`) — チェーンが途切れずに続いている回数。カードを取得/パターン継続でめくるたびに+1され(黄金の護符所持時は+2)、条件を満たさずめくった場合や手詰まりで0にリセットされる(誠実所持時はパターン継続のたび追加で加算される)。
- **基礎コンボ数**(`baseComboCount`) — コンボリセット後の再開値。祝福・剛毅・沈着・冷静などの護符によって永続的に加算され、以後コンボがリセットされてもこの値から再開する。
- **チェーン内での計算用コンボ**(`effectiveCombo`) — スコア計算のその場限りで使う一時的なコンボ値。基礎コンボ数を含み、庇護・大地などの護符がさらにこの値だけを底上げ/加算する。実際に保存される`wave.combo`自体は変化しない。
- **捨て札**(`discardPile: Card[]`) — コンボリセット時にチェーンにあったカードが送られる、ウェーブ限定の一時置き場。不屈・再生の護符が復活時にここから場札へ戻す。ウェーブをまたいで持続しない。
- **デッキ構成**(`DeckCard[]`, `deckComposition`) — ラン全体で持続する、山札の中身(スート・ランク・ワイルド判定)の構成。永劫・豊穣・静寂の護符や虚(天啓)によって書き換えられ、以後のウェーブにも引き継がれる。
- **ワイルド**(`wild: boolean`) — その時点で必要とされるランク・スートの代役として振る舞うカード。判定ごとに都合の良いランク・スートとして独立に解釈される(詳細: `shidasu-current-rules.md` 4.7節)。

## 3. スコアリング

- **獲得点**(`gained`, `lastGain: ScoreGain`) — 1回のプレイ/めくりで実際に加算される点数。基礎点+チェーンボーナス+列一掃ボーナスに、所持護符の加算・倍算効果とコンボ倍率等を順に適用した値(詳細な計算順序: `shidasu-current-rules.md` 4.1節)。
- **コンボ倍率**(`multiplier`) — `1 + effectiveCombo × comboMultiplierStep(既定0.1)`。コンボが伸びるほど際限なく上昇する。
- **パターンボーナス** — チェーン全体が共通の条件(同スート・同色・階段・交互)を保ち続けている間、条件を満たすたびに毎回加点されるボーナス。条件が一度でも崩れると、そのコンボがリセットされるまで二度と成立しない。山札めくりでの「パターン継続」判定もこの4条件を対象にする。
- **役ボーナス** — パターンボーナス以外の全ての加点条件の総称。直近数枚の窓(フラッシュ・ロイヤルセット)、チェーン内の出現回数(同ランク・ペア)、到達種類数(コンプリートラン)、列の状態(列一掃)など、チェーン全体の連続性に依存しない条件で判定される。途中でスート・色・階段が崩れていても独立して成立しうる。
- **役・パターン**(`RoleName`) — チェーンボーナスの種類名。役ボーナス6種(`flush`/フラッシュ・`royalSet`/ロイヤルセット・`sameRank`/同ランク・`completeRun`/コンプリートラン・`columnSweep`/列一掃・`pair`/ペア)とパターンボーナス4種(`suit`/同スート・`color`/同色・`stair`/階段・`alternating`/交互)の計10種類。いずれも神託によるレベル永続強化(成立するたびレベル+1)の対象。
- **列一掃** — 場札の1列を最後の1枚まで取り、その列が空になった時に成立する役ボーナス。「連続コンボが始まった時点でその列が(ほぼ)全段残っていたか」が条件になる。
- **全消し**(`endReason: 'fullClear'`) — 場札が0枚になった瞬間にウェーブが終了する状態。全消しボーナスはそのプレイの獲得点(gained)計算に統合され、コンボ倍率・乗算系護符・星の得点ロックの影響を受ける。
- **目標達成**(`endReason: 'target'`) — プレイ後のスコアがそのウェーブの目標スコア以上になった瞬間にウェーブが終了する状態。
- **手詰まり**(`endReason: 'stuck'`, `isStuck`) — 場札が1枚以上残っているのに山札が0枚で、かつ取得可能な列が1つもない状態(ダガズ(秘儀)所持中かつ捨て札があれば例外)。操作後600msの無操作を検知して判定される。

## 4. アイテムシステム

- **護符**(①Talisman, `ItemId`, `talismans`) — ウェーブクリア時の選択やショップ購入で入手し、以後常時発動するパッシブ効果。自由命名。現在99種類実装済み。
- **秘儀**(②Rite, `RiteId`, `rites`) — 北欧ルーン文字(エルダー・フサルク)をモチーフにした、プレイ中に能動的に使用する消費アイテム。全24種類実装済み。ウェーブを跨いで永続所持(所持上限3)。
- **天啓**(③Revelation, `RevelationId`, `revelations`) — 二十八宿をモチーフにした、いつでも使用可能で場札・デッキ構成の両方に永続効果を発揮する消費アイテム。28宿中12宿を効果実装済み(残り16宿は将来拡張用に温存)。
- **神託**(④Oracle) — 六十四卦をモチーフにした、10の役・パターンいずれかのレベルを永続+1する消費アイテム。天啓と所持枠を共有(合算上限2)。
- **護符オファー**(`offer: ItemId[]`, `rollItemOffer`) — ウェーブクリア時に未所持の護符から最大3個ランダムに提示される選択肢。秘儀・天啓・神託にも同様のオファー機構がある。
- **所持上限**(`items.maxItems`, 既定5) — 護符を同時に保持できる最大枚数。上限到達時に新しい護符を選ぶと、既存の護符と入れ替えるステップに切り替わる(`confirmItemSwap`)。
- **所持順解決** — 加算・倍算型の護符が複数所持されている場合、効果の適用順は所持順(`items`配列の並び順)に固定されるという大原則。ショップ画面でドラッグ&ドロップによる並べ替えが可能で、常設バッジ表示にも反映される。
- **護符名**(`talismans[id].name`) — 護符の表示名。`/admin/shidasu-talismans`で編集可能な`talismans[id].name`パラメータに統合されている。
- **効果説明文**(`itemDesc(id, params)`) — 護符の効果を、現在のパラメータ値を埋め込んで動的に生成する説明文。ゲーム内のアイテム選択画面や管理画面のプレビューに表示される。
- **通貨(星片)**(`currency`, `☆`) — ウェーブクリアごとに獲得し、ショップでアイテムを購入するのに使う。
- **ショップ**(`rollShop`) — ウェーブクリア後に立ち寄る、護符・秘儀・天啓・神託を購入できる画面。バラ売り3枠+福袋2枠で構成される。
- **トランプセット福袋**(`packKind: 'cardSet'`, `cardSets.ts`) — バラ売りが無い福袋限定の商品。開けると23種類のセットジャンル(階段・同ランク・絵札・同スート・ロイヤル・フラッシュ・コンプリートラン・ペア・赤黒バランス・ワイルド)から重み付き抽選で候補が提示され、選ぶと即座に`RunState.deckComposition`へカードが永続追加される。所持枠・スワップ処理は無い(選択即確定)。
- **ショップリロール**(`rerollShop`, `shopRerollCost`) — バラ売り3枠+福袋2枠を一括で再抽選するボタン。売り切れ済みの枠も含めて全て入れ替わる。通貨消費で、同一ショップ訪問中のリロール回数(`RunState.shopRerollCount`)に応じてコストが増額する。

## 5. 内部実装の分類用語

- **gainedチャンネル / clearBonusチャンネル**(`ITEM_EFFECTS`, `ItemEffect`) — 護符の加算・倍算効果が、獲得点(`gained`)と全消しボーナス(`clearBonus`)のどちらに作用するかを表す区分。`applyItemEffects`が`items`配列の並び順(所持順)に効果を適用する。
- **永続累積型**(献身・勤勉・加護・果断・星霜・残響・流星などが該当) — 対象条件を満たすたびにラン全体で永続する専用カウンタ(例: `dedicationX`・`discretionN`・`echoX`・`shootingStarN`)を加算し、その値を以後のgained計算に反映するパターン。`RunState`に正本を持ち、`WaveState`にコピーされてウェーブ間を橋渡しする。

## 6. デバッグ・管理画面

- **デバッグサンドボックス**(`/admin/shidasu-debug`) — 実プレイセッションとは独立に、アイテムの付与/削除や場札・山札のカード入れ替えをその場で試せる検証用画面。
- **護符パラメータ設定ページ**(`/admin/shidasu-talismans`) — 護符の名前・数値パラメータ・効果説明文プレビューを1護符1行のテーブルで編集する管理画面。
- **秘儀・天啓・神託パラメータ設定ページ**(`/admin/shidasu-rites`・`/admin/shidasu-revelations`・`/admin/shidasu-oracles`) — 護符と同様の編集画面。
- **星パラメータ設定ページ**(`/admin/shidasu-bosses`) — waveSlotごとの星(目標倍率・報酬・制限内容)を編集する画面。URLパスは旧ボス構想時代の名残(`bosses`)のまま残っている。
- **通貨・全体パラメータ設定ページ**(`/admin/shidasu-currency`, `/admin/shidasu`) — 通貨関連パラメータ、およびレイアウト・スコアリング・フロー・展開(spreads)・役ボーナス等の全体パラメータを編集する管理画面。
