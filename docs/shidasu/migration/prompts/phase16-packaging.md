# フェーズ16: Steam向け最小パッケージング・総合動作確認

> このプロンプトは、Shidasu(Balatro風トランプソリティア型ローグライク)をGodot(C#)へ移植し、Steam向けPCゲームとして販売するプロジェクトの一部です。ゲームロジックはGodotに依存しないPure C#の`Shidasu.Core`ライブラリに実装し、Godotプロジェクト本体はそれを参照するNode/Controlベースの薄いアダプタ層(UI・入力・演出)として実装します。Godotプロジェクトは元のWebリポジトリ(Utilities-Svelte)とは別管理ですが、VSCodeのマルチルートワークスペースにより両方のファイルを参照できます。
>
> 着手前に必ず読むこと:
> - `Utilities-Svelte/docs/shidasu/migration/01-work-plan.md`(全体計画)
> - フェーズ2〜15すべての成果物(本フェーズはこれらすべてに依存する最終フェーズ)。特にフェーズ9の成果物(「UIなしでコンソール/テストから1Run分をシミュレートできる状態」)とフェーズ10のテストスイートは、通しプレイテストの前提として実際に一度動かして状態を確認しておくこと

## 目的

実績・クラウドセーブ等は明示的にスコープ外(後続フェーズ扱い)とした上で、「起動して最初から最後まで遊べる」を最低ラインとする配布可能な最小パッケージに仕上げる(ユーザー方針: Steam向け機能は最小限)。

## 前提・依存

- 依存: フェーズ2〜15すべて。本プロジェクトの最終フェーズであり、これより後の実装フェーズはない
- スコープ外(本フェーズおよび現行プロジェクト全体で対象外、後続の別プロジェクト/フェーズ扱い): 実績(Achievements)、クラウドセーブ、Steamワークショップ等の高度なSteamworks機能
- 「最小限」の基準: Steamworks連携は起動確認程度(Steamクライアント経由での起動が問題なくできること)に留め、それ以上のSDK機能(マッチメイキング、フレンド機能等)への着手は不要

## 作業内容

### 1. Godotのエクスポート設定

- Windows向けエクスポートプリセットの作成(実行ファイル名・アイコン・バージョン情報等)
- 必要に応じて他プラットフォーム(Mac/Linux)の要否をユーザーに確認する(work-planでは「Windows等」とのみ記載されており、Windows以外の対応範囲は未確定のため、着手時に確認すること)
- リリースビルドでのパフォーマンス確認(デバッグオーバーレイ等が本番ビルドに残っていないか確認)

### 2. Steamworks連携の検討(最小限)

- GodotSteam等のSteamworks連携プラグインを導入するか、あるいはSteamworksを使わない最小構成(Steamのランチャー経由での単純起動のみ)にするかを判断する
- 連携する場合でも、以下の範囲に留める: アプリID紐付け、起動確認(Steamオーバーレイが正しく機能するか程度)
- 実績・クラウドセーブAPIには着手しない(スコープ外)

### 3. ストアページ用素材の準備

- スクリーンショット撮影(タイトル画面・プレイ中・ショップ画面・結果画面等、フェーズ14で完成したビジュアルアセットが反映された状態で撮る)
- 必要であればトレーラー用の素材撮り(動画編集自体は本フェーズのスコープに含めるかユーザーに確認する)
- ストアページに必要な最低限の情報(ゲーム概要文、対応言語等)を整理する

### 4. 全フェーズ統合後の通しプレイテスト

- Run開始からAll Clear(全ステージクリア)またはGame Overまで、実際にプレイして通しで動作確認する
- 複数回(できれば異なるスプレッド10種すべてで最低1回ずつ)プレイし、フェーズ2〜9で移植したロジック・フェーズ11〜13のUI/演出・フェーズ15のオーディオが噛み合って破綻なく動くことを確認する
- フェーズ10で整備したxUnit(またはNUnit)テストスイートを実行し、全パスすることを確認する
- 動作確認中に発見した不具合は修正し、修正内容と再確認結果を記録する

## 参照すべき既存ファイル(Utilities-Svelte内)

- `Utilities-Svelte/docs/shidasu/migration/01-work-plan.md`: 全16フェーズの依存関係・スコープの正本。特に「フェーズ16の依存はフェーズ2〜15すべて」という位置づけを踏まえ、抜け漏れがあれば該当フェーズに差し戻す
- フェーズ9の成果物: 妨害行動32種・スプレッド10種を含めた1Run分のロジックが完成している前提の確認材料
- フェーズ10のテストスイート: 通しプレイテスト前に一度実行し、既知の不具合がないことを確認する

## 成果物・保存先

- Steam提出用ビルド一式(Godotプロジェクト側、エクスポート出力)
- 動作確認記録(`Utilities-Svelte/docs/shidasu/migration/`配下にドキュメント化。例: `16-playtest-record.md`。実施日・プレイしたスプレッド・発見した不具合と対応状況を記載)
- ストアページ用素材(スクリーンショット等。保存先はGodotプロジェクト側の適切なフォルダ、またはユーザー指定の場所)

## 完了条件

- [ ] Steamworks連携方針(導入する/しない、する場合はどの範囲か)が決定し、その範囲で実装済み
- [ ] 実績・クラウドセーブには着手していない(スコープ外であることが確認できている)
- [ ] ストアページ用スクリーンショットが一通り揃っている
- [ ] Run開始〜All Clear/Game Overまでの通しプレイが複数スプレッドで成功している
- [ ] フェーズ10のxUnit(またはNUnit)テストスイートが全パスしている
- [ ] 動作確認記録が`docs/shidasu/migration/`に保存されている

## 注意点

- 実績・クラウドセーブは明示的にスコープ外。要望が出ても本フェーズでは着手せず、後続の別フェーズ・別プロジェクト扱いとしてユーザーに確認を促す
- 「最低ライン」は「起動して最初から最後まで遊べる」こと。細部の作り込み(バランス調整の深追い、演出の追加磨き込み等)より、まず全体が通しで破綻なく動くことを優先する
- Windows以外のプラットフォーム対応・トレーラー動画編集など、work-planに明記のない追加スコープが必要になった場合は、着手前にユーザーへ確認する
