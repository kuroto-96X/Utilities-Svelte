# トランプセット福袋 候補一覧(検討用)

Shidasuロードマップ項目8「ショップで購入できる商品の検討」のうち、「トランプセットの福袋」の検討用一覧。福袋を開けると、複数のセットジャンル(階段セット・同ランクセットなど)がランダムに提示され、その中から1つ(または複数)選んでデッキに永続的に追加する新種の福袋を検討する。

本ドキュメントは候補の洗い出しのみが目的で、実装対象の選定・実装自体は別セッションで行う。

## 実装完了(2026-08-08)

候補11ジャンルを再検討し、「枚数バリエーションを独立ジャンルとして扱う」方針のもと23種類のセットジャンルを確定して実装した。詳細設計は`docs/superpowers/specs/2026-08-08-shidasu-card-set-pack-design.md`、実装は`src/lib/game/shidasu/cardSets.ts`(`CARD_SET_GENRE_NAMES`・`generateCardSet`)を参照。

- **枚数バリエーションの独立ジャンル化**: 元候補で「○枚」と固定していたジャンルのうち、階段セット・同ランクセット・同スートセットは3種類の枚数(階段/同スート: 3・5・7枚、同ランク: 2・3・4枚)、コンプリートランセットはスート決定方式(同スート統一/カードごとにランダム)、ペアセットは組数(2組・3組)、赤黒バランスセットは枚数(4・6・8枚)×スート決定方式(統一/カードごとにランダム)の組み合わせで、それぞれ独立したジャンルIDに分割した。絵札セット・ロイヤルセット・フラッシュセット・ワイルドカードは元候補のまま単一ジャンル。
- **抽選重み**: 各ジャンルの抽選重みは「1/枚数」(ワイルドカードのみ例外で1/6)とし、福袋を開けた瞬間に重み付き非復元抽選で提示ジャンルを確定する。
- **レインボー・ステアセットは不採用**: 対応する新規役「レインボー・ストレート」自体が`docs/shidasu/done/shidasu-role-candidates.md`で不採用となったため、このセットジャンルも実装対象から外した。

## 全体構造

既存の護符/秘儀/天啓/神託福袋(`packKind: 'item' | 'rite' | 'revelation' | 'oracle'`)と同じ枠組みを踏襲する。

- 新しい`packKind`(例: `'cardSet'`)を追加し、既存の`PACK_DEFINITIONS`(`src/lib/game/shidasu/shop.ts`)と同様に`offerCount: 3 | 5 | 7`・`pickCount: 1 | 2`のパターンを持つ
- 福袋を開けると、後述の「セットジャンルプール」からランダムに`offerCount`個のジャンルが選ばれて提示される。既存の護符福袋が「プールから複数の護符IDをランダム抽選」する仕組みと同じで、プールの中身が「護符ID」ではなく「セットジャンル」になる点が違い
- 各オファーの中身(具体的なスート・ランクの組み合わせ)は、福袋を開けた瞬間にジャンルごとの制約内でランダムに1回だけ確定する(選択肢を表示する時点で既に確定済みのカード内容を見せる、既存の「オファーは開封時に一度だけ抽選される」設計方針を踏襲)
- 選んだセットのカードは`RunState.deckComposition`に恒久的に追加される(以後のウェーブすべてに反映される、ラン全体で持続する変更)

## カード重複の扱い

標準デッキは既に52枚全部(各スート×各ランク1枚ずつ)が`deckComposition`に存在する。トランプセット福袋で新規追加するカードは、**既存デッキ(または他の福袋で過去に追加されたカード)と同じ(スート, ランク)の組み合わせが重複することを許容する**(例: ♠Aが2枚目・3枚目と増えていく)。`deckId`はカードごとに個別採番されるため、ゲーム内部では別々のカードとして問題なく扱える。

以下の一覧で「重複無く選択」と書いている箇所は、**そのセット1つの中でのみ**重複を避ける(例: 同ランクセットで同じスートを2回使わない)という意味であり、既存デッキや過去の福袋で追加されたカードとの重複は考慮しない。

## 技術的な新規要素

現在の`RunState.deckComposition`は、ラン開始時に`standardDeckComposition()`(52枚固定)で初期化された後、個々のカードを`wild: true`に変換する処理(`convertCardToWildByDeckId`、静寂の護符・天啓のワイルド変換で使用)はあるが、**新しいカードを配列に追加する処理は現状存在しない**。トランプセット福袋の実装には、`deckComposition`に複数枚のカードを一括追加する新規関数が必要になる。

追加されたカードの`deckId`は、既存の最大値の続きから採番する(天啓のワイルド供給処理`revelationEffects.ts`74行目付近の`newDeckId`と同じ採番方式を踏襲できる)。

## 難易度・価格帯の考え方

既存の護符福袋の価格帯(3-1: 4星片、5-1: 6〜7星片、7-2: 8〜10星片)を参考にしつつ、セットジャンルごとに「デッキへの影響度」で価格を調整する想定。

- **軽量級**(3〜4枚、既存パターン・役の必要最小枚数相当): 同ランクセット・絵札セット・ペアセット・ワイルドカード
- **中量級**(4〜5枚、複合条件や既存役1つ分を即座に満たす): 階段セット・同スートセット・ロイヤルセット・フラッシュセット・レインボー・ステアセット
- **重量級**(6枚以上、デッキ構成への影響が大きい): 赤黒バランスセット・コンプリートランセット(特にコンプリートランセットは最上位価格帯を想定)

具体的な価格・レア度の数値は、実装時に既存の`packPrice`テーブル(`shidasu.config.json`)と同じ形式で決定する。

## 除外・非対象

- 「セットの中身を選ぶ」UI(例: 同スートセットでどのスートにするか自分で選択する)は対象外。ロードマップの元記述通り、ジャンルを選んだ後の具体的なカード内容は完全ランダムとする
- デッキから既存カードを除去・変換する効果(縮小・純化系)は本ドキュメントの対象外。トランプセット福袋は「追加専用」の仕組みとして検討する
- ペアセット・レインボー・ステアセットが対応する新規役(ペア・レインボー・ストレート)自体の実装可否は、`docs/shidasu/done/shidasu-role-candidates.md`側の検討事項だった(ペアは採用・実装済み、レインボー・ストレートは不採用)。ペアセットは役が実装済みのため`pair2`/`pair3`として採用、レインボー・ステアセットは対応する役が不採用となったため実装対象から外した(上記「実装完了」参照)
