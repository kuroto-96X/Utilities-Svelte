# 報酬増加系護符 候補一覧(検討用)

Shidasuロードマップ項目1「『報酬増加系の護符』の追加を検討する」のための、名前候補・効果の方向性・個別効果をまとめて検討するワークシート。「報酬増加系」は星片(ゲーム内通貨)を直接増やす方向の護符を指す。

このドキュメントは複数セッションにまたがって育てていく想定。名前候補(80個)・方向性(3個)は決定済み(2026-08-22)。個別の効果は方向性ごとに1つずつ検討を進めており、以降のセッションで随時この下の「個別効果の検討」セクションに追記していく。

## 制約

- 全て**二文字の漢字のみ**で構成する(ひらがな・カタカナ・3文字以上は対象外)
- 既存の護符名99個(`src/lib/game/shidasu/shidasu.config.json`の`talismans`)と重複しない
- 金運・商売・繁盛・実り・利益・報酬・縁起・栄達をテーマとし、既存99個の傾向(自然現象・美徳・宝石・運命系の語彙が中心)とは異なる方向性で選定した
- 「福袋」はショップの既存パック(福袋、`packKind`)の名称と意味が衝突するため候補から除外した
- 「実り」「埋蔵金」「大入り」は二文字漢字の制約(ひらがな混じり・3文字)を満たさないため候補から除外した

## 効果の方向性(3個)

検討の出発点として5つの方向性案があったが、うち2つは既存のレリック(招き猫・開運こけし・数珠・千社札・算盤)が既にカバーしている領域と重複するため、検討対象から除外した(2026-08-22判断)。

- **除外1: 護符・秘儀・神託・天啓の売値の操作** — レリック「招き猫」(購入価格割引)・「開運こけし」(売却価格増加)が既に全アイテム一律の売買価格操作を担っている。
- **除外2: Waveクリア時に追加報酬(星片の利息や所持アイテムの数や売値に応じた報酬など)** — レリック「数珠」(利息系)・「千社札」(所持数ボーナス)・「算盤」(売値ボーナス)が既にWaveクリア時の追加報酬を担っている。

レリックは少数精選で無条件・大規模な一律効果、護符は多数の中から個別の小さな効果を組み合わせる設計という位置づけの違いがあり、両者が同じテーマ(報酬)を扱うこと自体は問題ないが、上記2件は既存レリックと効果の中身が直接重複するため除外した。

残った3方向性を検討対象として確定した:

1. **特定行動で自分自身の売値を増加**: 護符自身の売却価格を、プレイ中の特定の行動・条件によって一時的または永続的に上昇させる。護符本体の価値を操作する方向性。
2. **プレイ中に特定条件を満たした場合に即時報酬**: カードプレイ中、特定の役が成立した・特定のスートやランクがチェーンに含まれている等の条件を満たした瞬間に、星片を即座に獲得する。既存の「得点内訳(gained/clearBonus)」パイプラインとは別の、通貨(`currency`)への直接加算という新しい経路になる。
3. **秘儀・天啓・神託使用時にキャッシュバック**: 秘儀・天啓・神託を使用(消費)した際、使用したこと自体をトリガーとして星片を獲得する。アイテム運用(使う・貯める)という行動そのものに報酬を結びつける方向性。

## 個別効果の検討

方向性ごとに1つずつ、効果の例をたたき台にして検討を進める(2026-08-22〜)。どの名前にどの効果を割り当てるかの最終確定は、3方向性すべての効果候補が出揃ってから行う。

### 方向性1: 特定行動で自分自身の売値を増加

**前提条件(未解決)**: 現在の`RunState.items`は`ItemId[]`という単純な配列で、同名護符を複数所持していても個体を区別できない。「自分自身の売値を増加」させるには、護符をレリック(`{ id, tsukumoka }`)と同様の「個体ごとに状態を持つオブジェクト配列」に変える必要がある。この変更は`engine.ts`・`shop.ts`・`itemActualEffects.ts`・`+page.svelte`・`PlayArea.svelte`など9ファイル以上に影響し、既存の封印・没収・バッジ表示など多数の実装(`activeSeal`の`id`ベース判定を含む)に波及する大規模な変更になる。具体的なデータ構造設計・移行方法は**別セッションでdesign docを作成して検討する**(本ワークシートでは前提条件として記録するのみ)。

**効果候補(22個)**: いずれも既存の護符カテゴリが使っているトリガー条件を、得点増加ではなく「自分自身の売値増加」という報酬軸に転用する方針。追加検討時、「通常プレイで絶対に発生する条件は避ける」という基準を設けた(下記「却下した候補」参照)。

**却下した候補**: 「通常プレイで絶対に発生する条件は避けたい」という基準により、以下は候補から除外した。
- 山札をめくるたび: プレイのたびにほぼ毎回発生し高頻度すぎる。
- 最大コンボ数を更新するたび: 実質「そのWave中の最大コンボ数」と同じで条件が緩すぎる。
- Wave1枚目をプレイしたとき: 一見Waveごとに1回の希少な条件に見えるが、Waveごとに必ず1回発生する(スキップ不可)ため、厳密には「絶対発生する条件」に該当し却下。

**未確定事項**:
- 22個すべてを採用するか、一部に絞るかは未定。特に候補5・10・11・12(♠A・♥K・♦J・♣Q)は「特定1枚のカード」という新規パターンで4つ並んでいるため、既存の「スート単体4種」(春風・夏風・秋風・冬風)と似た並びになる。4つ全部を採用するか、絞るかは実装検討時に判断する。同様に候補14〜17(パターン4種+mの閾値)、候補18〜21(役4種)もそれぞれ既存の「役・パターン成立状況」グループ(恩寵・集中・瑠璃・翡翠・無心)と並ぶボリュームになるため、実装時にどこまで採用するか絞り込みが必要になる可能性が高い。
- パターン系(候補14〜17)の閾値mの具体的な値は未定。基本成立条件(3枚以上・4枚以上)よりどの程度高くするかは実装計画作成時に決定する。
- 候補2a/2b/2cの具体的なC(易・中・難の各閾値)・N(各加算量)の値は未定。
- 候補22「他の護符を売却するたび」は、加算量が固定Nではなく動的な値(売却した護符の売値)になる初めての候補。永続的な蓄積ロジック(前提条件で触れたitemsのオブジェクト化)との組み合わせ方は別セッションで詰める。
- 売値上昇が永続(Wave・ラン全体を通して蓄積)か、一時的(次のWave開始でリセット等)かは未定。
- 上昇量`N`・上限の有無は未定。
