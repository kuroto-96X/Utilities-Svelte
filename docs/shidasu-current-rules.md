# 星詠みソリティア -Shidasu- 現行仕様書

`src/lib/game/shidasu/{engine,params,types,deck}.ts`の実装内容を元にした、現時点(護符刷新後)のゲームルール仕様書。護符のバランス検討など、今後の設計作業の土台として参照する。数値は全て既定値(`DEFAULT_PARAMS`/`shidasu.config.json`、両者は常に同一)。

## 1. 概要

トランプ1組(52枚、ジョーカーなし)を使うソリティア風のスコアアタックゲーム。場札(tableau)の各列の一番手前のカードを、基準カード(foundation)とランクが±1(またはK⇔Aループ)であれば取れる。取ったカードが新しい基準カードになる。連鎖(コンボ)を繋いでスコアを稼ぎ、ウェーブごとの目標スコアを超えればクリア。

## 2. 進行構造(Run > Stage > Wave)

- **Run(1周)**: 3ステージ×各3ウェーブ=**計9ウェーブ**を順にクリアしていく。全ウェーブクリアで「全ステージクリア(allClear)」。
- **Stage(ステージ)**: 3つ存在し、それぞれ固有の制約(`modifier`)と、ウェーブごとの目標スコア(`targets`)を持つ。

  | ステージ | 制約(modifier) | ウェーブ1目標 | ウェーブ2目標 | ウェーブ3目標 |
  |---|---|---|---|---|
  | STAGE 1 | none(制約なし) | 4000 | 7500 | 13000 |
  | STAGE 2 | noLoop(A-Kループ禁止) | 6000 | 11000 | 19000 |
  | STAGE 3 | faceLock(絵札はコンボ2以上でのみ取れる) | 8000 | 15000 | 26000 |

- **Wave(1回のプレイ)**: 山を1組配り直して、目標スコアに届くか、場札を全消しするか、山札が尽きて手詰まりになるまで続く1回のプレイ単位。

### フェーズ遷移

`RunState.phase`は以下を遷移する: `title`(タイトル画面)→`playing`(プレイ中)→(ウェーブ終了)→`itemSelect`(アイテム選択、最終ウェーブ以外)or`stageClear`(ステージ内最終ウェーブクリア、最終ステージ以外)or`allClear`(全クリア)or`gameOver`(目標未達)。

- ウェーブ終了時、目標スコア未達なら結果に関わらず即座に`gameOver`。
- 目標達成かつステージ内最終(3ウェーブ目)でなければ`itemSelect`(護符オファーを提示)。
- 目標達成かつステージ内最終だが最終ステージでなければ`stageClear`(次ステージへ進む選択肢のみ)。
- 目標達成かつ最終ステージの最終ウェーブなら`allClear`。

## 3. 場札・山札の初期配置

- 場札(tableau): `cols`列×`rows`段 = **7列×5段=35枚**を裏向き山から配る(各列の一番奥=先頭、一番手前=末尾)。
- 基準カード(foundation): 場札配布後の山から1枚。
- 山札(stock): 残り **52-35-1=16枚**。
- 現行の山札生成(`createDeck`)は常に**ワイルドカードを含まない標準52枚**。ワイルドカードを供給する手段は現状存在しない(後述4.7参照)。

## 4. スコアリング詳細

### 4.1 基本の加点式

1枚プレイするごとに、以下の式で加点される:

```
gained = floor(base × multiplier)
```

- `base = basePoint(100) + チェーンボーナス合計 + 列一掃ボーナス(成立時のみ)`
- `multiplier = 1 + (今回のコンボ数 - 1) × comboMultiplierStep(0.1)`
  - コンボ1(倍率1.0)、コンボ2(倍率1.1)、コンボ3(倍率1.2)…と際限なく上昇する(上限なし)。

### 4.2 チェーンボーナス(`evaluateChainBonus`)

プレイ済みチェーン(`chain`、直前までに取った/引いたカードの履歴)を元に、以下を**それぞれ独立に**判定して合算する。チェーンが空(ウェーブ開始直後の1枚目)の場合はボーナス0。

| ボーナス名 | 条件 | 加点 |
|---|---|---|
| 同スート | チェーン直前がワイルドでなく、チェーン内の実カードが全て同じスート | +100(suitBonus) |
| 同色 | 同スート不成立、かつチェーン内の実カードが全て同じ色(赤/黒) | +50(colorBonus) |
| ★同スート | チェーンの直前のカードがワイルドだった場合、上記2つの代わりに固定で加算 | +100(wildSuitBonus) |
| 階段 | チェーンが同方向(+1固定)に連続しており、長さが最小連続枚数以上 | +150(stairBonus) |
| フラッシュ | 直近4枚(実カード+ワイルド)で♠♥♦♣が全て揃う(ワイルド1枚につき不足スート1つを埋められる) | +300(flushBonus) |
| ロイヤルセット | 直近3枚でJ・Q・Kが揃う(ワイルド1枚につき不足ランク1つを埋められる) | +400(royalSetBonus) |
| 同ランク | チェーン内に同じランクの実カードが既にn枚あれば、n×固定値 | 100×既出枚数(sameRankBonusUnit) |
| コンプリートラン | このプレイで初めて13ランク(実カード+ワイルド、13で頭打ち)が出揃った瞬間 | +1000(completeRunBonus) |
| コンプリートラン(同スート) | コンプリートラン成立時、実カードが全て同じスートなら追加 | +1000(completeRunSuitBonus) |

**階段の最小連続枚数**: 既定は**5枚**(`stairMinLen`)。「架橋の護符」を持っていれば**3枚**(`stairRelaxedMinLen`)に緩和される。

**ワイルドによる役穴埋め(フラッシュ/ロイヤルセット/コンプリートラン)**: ロジックは実装済みだが、現状ワイルドカードの供給手段が無いため実プレイでは発動しない(4.7参照)。

### 4.3 列一掃ボーナス

場札の列を最後の1枚まで取り、その列が空になった時に加算される。

- **基本ルール**: その列が「現在の連続コンボが始まった時点(直近でコンボがリセットされた瞬間)」で**全5枚(rows)残っていた**場合のみ成立する。つまり、**1回も途切れていない連続コンボの中で列を丸ごと消化しきった場合のみ**ボーナス対象になる。
- **寛容の護符**所持時: 「連続コンボ開始時点で残り`rows - columnSweepRelaxCards`枚(既定5-2=**3枚**)以下だった」場合も対象になる(列の残り数枚だけを1コンボで消化すればよい、という緩和)。
- 加点額: `columnSweepBonus(150) × 同じコンボ内で今まで一掃した列数`。同じコンボ中に2列目を一掃すると150×2=300、3列目なら150×3=450…と列数倍で増えていく。

### 4.4 全消しボーナス

場札が0枚になった瞬間、そのウェーブは即座に終了(`endReason: 'fullClear'`)し、以下が**コンボ倍率を通さず加点式の外側で**加算される:

```
clearBonus(2000) + 残り山札枚数 × clearBonusPerStock(50)
```

### 4.5 目標スコア到達

全消し前にプレイ後のスコアが目標(`target`)以上になった時点で、そのウェーブは即座に終了(`endReason: 'target'`)する。

### 4.6 山札めくり(ドロー)

山札からめくると、以下のいずれかが起こる:

1. **ワイルドを引いた場合**: コンボは変化せず、チェーンに追加されるだけ(得点は発生しない)。`lastDrawEffect: 'wild'`。
2. **パターン継続の場合**(`chainContinuesPattern`): 直前のチェーンが同スート/同色/階段のいずれかで繋がっており、めくった札がその継続条件を満たす場合、コンボを維持したままチェーンに追加(得点は発生しない)。`lastDrawEffect: 'pattern'`。
   - 判定は独立した2系統のOR: (a)同スートが成立中ならスートが一致するか、同スート不成立で同色が成立中なら色が一致するか(同スート判定が優先、両方は同時に見ない)、(b)階段が成立中(方向確定済み)ならその方向を継続するランクか。(a)(b)のどちらか一方でも満たせば継続。
3. **上記いずれにも該当しない場合**: コンボが0にリセットされ、めくった札1枚だけの新しいチェーンとして再スタートする。列一掃カウント(`columnsEmptiedThisCombo`)と、各列の「連続コンボ開始時点の残り枚数」スナップショット(`comboStreakColumnLengths`)もこの瞬間に取り直される。

山札が0枚の状態でめくり操作をしても何も起こらない。

### 4.7 ワイルドカードについて(現状の制約)

チェーン継続・役判定(同スート・階段・フラッシュ・ロイヤルセット・コンプリートラン)には全てワイルド対応のロジックが実装されているが、**現在の山札生成には一切ワイルドカードが含まれない**(かつて存在した「ワイルド★」アイテムが2026-07-09に削除されたため)。したがって現状のプレイでは、ワイルド関連の分岐は発生しない。将来ワイルドを山札に供給する新規アイテムが追加された際に機能する先行実装として温存されている。

## 5. 場札が取れる条件(`isPlayable`)

列の一番手前のカードは、以下を満たせば取れる:

1. **faceLock制約中**、かつそのカードが絵柄(J/Q/K、ランク11以上)で、かつ現在のコンボが2未満の場合 → **取れない**(この判定が最優先。基準カードがワイルドでも絵札自体がワイルドでない限り無効化されない)
2. カード自身がワイルド、または現在の基準カードがワイルドの場合 → 取れる
3. ランク差(|カードのランク - 基準カードのランク|)が1 → 取れる
4. ランク差が12(A⇔Kの境界)、かつ**noLoop制約でない**場合 → 取れる
5. 上記いずれにも当てはまらなければ取れない

## 6. ステージ制約(modifier)一覧

| modifier | 効果 |
|---|---|
| none | 制約なし。A⇔Kのループも可能 |
| noLoop | A⇔Kのループ(ランク差12)による接続を禁止する |
| faceLock | 絵札(J/Q/K)は、現在のコンボが2以上の時のみ取れる(コンボ0・1では絵札を拒否) |

## 7. 手詰まり判定(`isStuck`)

場札が1枚以上残っており、山札が0枚で、かつ取れる列が1つもない場合に手詰まりと判定され、ウェーブが`endReason: 'stuck'`で終了する(場札が0枚なら手詰まりではなく全消し扱い)。UI側では、操作後600msの無操作を検知してこの判定を実行する。

## 8. 護符(①アイテム)システム

- ウェーブクリア時(ステージ内最終ウェーブを除く)、未所持の護符から最大3個(現状プールは2個のみなので2個以下)がランダムに提示され、1個を選んで次のウェーブへ進む。
- **全ての護符は1種類につき最大1個まで**しか所持できない(既に持っている護符は以降のオファーに出現しない)。
- 現行の護符プール(2個):

  | 護符名 | 効果 |
  |---|---|
  | 架橋の護符 | 階段成立に必要な最小連続枚数を5→3枚に緩和 |
  | 寛容の護符 | 列一掃ボーナスの条件を「列の全5枚を1コンボで空に」→「残り3枚から1コンボで空に」に緩和 |

  (両方を取り尽くすと、以降のウェーブクリア時のアイテム選択肢は空になる。今後の護符追加で解消される想定。)

## 10. アイテム以外の分類(将来拡張、現状未実装)

`docs/shidasu-roadmap.md`・`docs/superpowers/specs/2026-07-09-culmen-theme-and-item-motif-design.md`で構想されている、①護符以外の3種類(②秘儀/Rite・③天啓/Revelation・④神託/Oracle)は未実装。現状実装されているのは①護符のみで、いずれも「ウェーブクリア時に選び、以後は常時発動するパッシブ効果」という単一の発動方式に限られる(プレイ中に能動的に使う操作は存在しない)。
