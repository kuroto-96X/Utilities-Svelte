# 誓約・契り(デメリット付き倍算)と紅蓮・漆黒(色拡張イネーブラー) 設計

## 背景・目的

`docs/shidasu/shidasu-gofu-candidates.md`のグループ18(紅蓮・漆黒)・グループ19(誓約・契り・白銀)は未実装のまま残っていた。今回はこのうち相互に密接に絡む4個(誓約・契り・紅蓮・漆黒)を1つのまとまりとして実装する。白銀・果断・星霜は別途進める。

- **誓約**(U): コンボ内の札と同じ色の札しか取れなくなるが倍算
- **契り**(R): コンボ内の札と同じスートの札しか取れなくなるが倍算
- **紅蓮**(U): 全ての札が赤の札としても扱われる
- **漆黒**(U): 全ての札が黒の札としても扱われる

紅蓮・漆黒は単体では地味だが、誓約(色制約)を緩和するイネーブラーとして機能させる。また、既存の色判定を使う護符・秘儀(月光・陽光・宵闇・払暁・均衡・調和・ヴンヨー・ラグズ)にも一貫して影響させる。

## スコープ

対象: 誓約・契り(新規制約付き倍算護符)、紅蓮・漆黒(新規色拡張イネーブラー護符)、および紅蓮・漆黒を反映するための`isRed`利用箇所全体の改修。

対象外: 白銀、果断、星霜(別途実装)。

## 設計

### 誓約・契りの制約ロジック

`isPlayable`(`engine.ts`)の既存条件(ランク隣接判定)に加えて、以下を追加する。

- 誓約所持時: 取ろうとしているカードが、`wave.chain`の最後の1枚(直前にチェーンへ加わった実カード)と「色が一致しうるか」(後述のcardColorsベースの判定)を満たさなければ取れない。チェーンが空(ウェーブ最初の1枚)なら制約なし
- 契り所持時: 同様に「スートが一致するか」を満たさなければ取れない。スートには紅蓮・漆黒のような拡張解釈は適用しない(契りには緩和策を用意しない)

誓約・契りを同時に所持している場合、両方の制約が同時に課される(AND条件)。

`isPlayable`は`items: ItemId[]`(所持護符)と`wave.chain`を新たに参照する必要があるため、シグネチャに`items`引数を追加する。呼び出し元(`engine.ts`内・`PlayArea.svelte`)を全て更新する。

倍率: 誓約はx2、契りはx3(スートの方が制約が厳しいため高め)。既存の同系統護符(月光・陽光=x1.5、真剣・聖杯等=x3)を参考にした値。

### 紅蓮・漆黒による色拡張解釈(cardColors)

`isRed(card): boolean`を、紅蓮・漆黒を考慮した`cardColors(card: Card, items: ItemId[]): { red: boolean; black: boolean }`に置き換える。

- 通常時: `card`が♥♦なら`{ red: true, black: false }`、♠♣なら`{ red: false, black: true }`(ワイルドの扱いは既存通り、呼び出し元で個別に処理)
- 紅蓮所持時: `red`は常に`true`(元の色に関わらず)。`black`は元の色のまま
- 漆黒所持時: `black`は常に`true`。`red`は元の色のまま
- 両方所持時: `red`も`black`も常に`true`

つまり紅蓮所持中の黒札は「黒かつ赤」の両方の性質を持つカードとして扱われる。

### 各既存判定への適用方法

`isRed`を使っていた9箇所を、判定の意味合いに応じて以下のパターンで`cardColors`ベースに書き換える。

1. **同色一致判定**(`analyzeSuitColor`の`colorHeld`、誓約の色制約): 2枚のカードが共通の色を持つか。`(a.red && b.red) || (a.black && b.black)`
2. **単色専有判定**(月光=黒のみでコンボ、陽光=赤のみでコンボ、`chainColorExclusive`): チェーン内の全実カードが対象色を含むか。`chain.every(c => c.wild || cardColors(c, items).black)`のように「含む」で判定
3. **切替検出**(宵闇=直前赤→今回黒、払暁=直前黒→今回赤): 直前カードが一方の色を含み、かつ今回カードがもう一方の色を含むか。`cardColors(prev, items).red && cardColors(curr, items).black`のように「含む」の組み合わせで判定する。この方式により、紅蓮所持中は黒札同士の連続でも「黒札は赤も含む」ため宵闇・払暁どちらも成立しうる(意図した挙動)
4. **赤黒枚数判定**(均衡・調和の`redBlackBalanced`、秘儀のヴンヨー・ラグズの`redCount`/`blackCount`集計): 紅蓮所持時、該当色を含むカードを枚数にカウントできる、というワイルドと同様の「都合の良い解釈」を適用する。具体的には、赤の枚数を数える際は`cardColors(c, items).red`を満たすカードを数え、黒の枚数を数える際は`.black`を満たすカードを数える(紅蓮所持中は黒札も赤カウントに算入されうる)

### 秘儀(ヴンヨー・ラグズ)への反映

`applyRiteEffect`(`riteEffects.ts`)は現在`items`を引数に持たないため、シグネチャに`items: ItemId[]`を追加し、呼び出し元(`useRite`相当の関数)から渡す。`applyWunjo`・`applyLaguz`内の`redCount`/`blackCount`集計を`cardColors`ベースに書き換える。

## テスト方針

`engine.test.ts`に以下を追加する。

- 誓約所持時、チェーン最新札と異なる色のカードは`isPlayable`が`false`になること
- 契り所持時、チェーン最新札と異なるスートのカードは`isPlayable`が`false`になること
- 誓約+紅蓮所持時、黒札のチェーンに対して黒札を取ろうとした場合(色が一致)は取れること。さらに紅蓮により黒札が「赤も含む」ため、赤札のチェーンに対しても黒札が取れること
- 誓約のみ(紅蓮なし)なら、上記の赤黒混在パターンは弾かれること
- 月光(黒のみコンボ)が紅蓮所持時、黒札のみのチェーンで成立すること(紅蓮の有無で結果が変わらないことも確認: 黒札は紅蓮があっても「黒を含む」ままなので月光は変わらず成立する)
- 宵闇・払暁が、紅蓮所持中の黒札→黒札の連続で両方成立しうること(通常時は成立しないことと対比)
- 均衡・調和(赤黒同数判定)が、紅蓮所持時に黒札を赤としてもカウントできる(都合の良い解釈で同数が成立しやすくなる)こと

`riteEffects.test.ts`にも、ヴンヨー・ラグズが紅蓮/漆黒所持時に赤黒判定へ反映されることを確認するテストを追加する。

ブラウザでの目視確認は行わず(スコア計算ロジックの検証はユニットテストで完結するため)、実装完了後のプロジェクト規約に基づく`npm run build`・`npm run check`・`npm run dev`の確認のみ実施する。
