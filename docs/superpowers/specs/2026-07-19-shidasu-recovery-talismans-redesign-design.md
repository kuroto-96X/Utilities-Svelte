# Shidasu 復活系護符(再生・治癒・不屈)再設計 設計

## 0. 背景・目的

再生・治癒・不屈の3護符の効果を、以下のように変更する(直感は対象外・変更なし)。

- **再生**: 「山札にカードがない場合、発動しない。全消し時、コンボリセットしてチェーンのカードをすべて捨て札に。スコアの50%を消費したあと、捨て札から場札を復活する。その後、山札を捲る。」
- **治癒**: 「コンボリセット時、そのコンボ内で列一掃を達成していた場合、捨て札から列一掃した列へ戻す。戻すカードの枚数はそのコンボ開始時の該当列の枚数まで」
- **不屈**: 「山札が無く場札も取れない手詰まり時、コンボリセットしてチェーンのカードをすべて捨て札に。スコアの30%を消費して捨て札の半数を山札に戻す。その後、山札を捲る。」

これに伴い、以下の横断的な変更も行う。

- 全消し・手詰まりでの「コンボリセット+チェーンの札を捨て札へ」は、護符の有無に関係ない共通処理とする
- 目標スコア判定は、スコアが変動するたびに毎回行う(達成していればその時点で即座にウェーブ終了し、以降の得点計算ステップは実行しない)
- 再生・不屈は、それぞれウェーブ中1回のみ発動する(スコア消費割合はパラメータ`p`%を使用、数値は変更なし: 再生50%・不屈30%)

パラメータ数値(`regeneration.p`・`resilience.p`)は変更しない。挙動(いつ・どう発動するか)のみを変更する。

## 1. 共通処理「コンボリセット」

現在`drawStock`のパターン不継続時リセット分岐に存在する以下の処理を、`resolveComboReset`のような共通ヘルパー関数として切り出し、3箇所(通常のdrawStockリセット・全消し時・手詰まり時)から呼び出せるようにする。

- `combo`を0(祝福所持時は`baseComboCount`)にする
- `chain`にあった札をすべて`discardPile`へ移す(`chain: [foundation]`にリセット)
- `columnsEmptiedThisCombo`・`comboStreakColumnLengths`・`roleEchoUsedThisCombo`・`sameRankEchoUsedThisCombo`・`pendingRoleEcho`・`benevolenceUsedThisCombo`・`flushActiveThisCombo`・`lastPlayedColumn`・`sameColumnStreak`・`drawContinueCountThisChain`など、既存のリセット分岐が初期化しているフィールドをすべて同様に初期化する
- 新規: `sweptColumnsThisCombo`(後述)を空配列にリセットする前に、治癒の解決に使う

**治癒の解決はこの共通処理の一部として行う。** 治癒を所持していれば、リセット直前の`sweptColumnsThisCombo`(そのコンボ中に列一掃を達成した列とその開始時枚数の一覧)を先頭から順に処理し、各列についてリセット後の`discardPile`(チェーンの札が加わった後)から最大`startLength`枚を復活させる。捨て札は1回だけシャッフルし、列一掃した順に在庫が尽きるまで割り振る。

この共通処理は、以下の3箇所すべてから呼ばれる(=治癒はこの3箇所すべてで発動しうる)。

1. **通常の`drawStock`リセット分岐**(パターン不継続によるコンボリセット。最も頻度が高い)
2. **`playCard`での全消し発生時**
3. **手詰まり発生時**(`applyStuckCheck`相当)

## 2. `WaveState`への追加フィールド

```ts
// 治癒用: 現在のコンボ中に列一掃を達成した列のインデックスと、その列のコンボ開始時点の枚数
sweptColumnsThisCombo: { colIndex: number; startLength: number }[]
// 再生用: ウェーブ中に再生が既に発動したか(ウェーブ中1回のみ)
regenerationUsedThisWave: boolean
// 不屈用: ウェーブ中に不屈が既に発動したか(ウェーブ中1回のみ)
resilienceUsedThisWave: boolean
```

`sweptColumnsThisCombo`は`playCard`で列一掃(`sweepQualifies`)が成立するたびに`{ colIndex, startLength: comboStreakColumnLengths[colIndex] }`を追加し、コンボリセットのたびに空配列へ戻す。`regenerationUsedThisWave`・`resilienceUsedThisWave`は`startWave`で`false`初期化し、発動時に`true`にする(ウェーブを跨いでは持続しない)。

## 3. 目標スコア判定の即時化

現在は`playCard`の末尾で1回だけ`newScore >= target`を判定しているが、これをスコアが変動する箇所すべての直後に行うよう変更する。達成していれば、その時点のスコアで即座に`status: 'ended', endReason: 'target'`として返し、以降の得点計算ステップ(コンボ到達直接加算・全消しボーナス・全消し時の護符処理など)は実行しない。

対象となる箇所(`playCard`側):
1. 護符gained+コンボ倍率適用後のスコア加算
2. コンボ到達時の直接加算護符(流星等)適用後
3. (全消し時のみ)全消しボーナス加算後

対象となる箇所(`drawStock`側、通常のパターン不継続リセット分岐):
4. 山札切れ時の直接加算護符(慢心)適用後
5. コンボリセット時の直接加算護符(沈着・冷静・回響)適用後

(パターン継続分岐の誠実・素朴による加算も同様に、それぞれの加算直後に判定する。)

いずれの箇所で目標判定が発生しても、この判定より後段の処理(全消し時の護符解決・コンボリセット・山札を捲る、等)は一切行わない。

## 4. 全消し時のフロー(`playCard`)

1. (既存)基礎点・チェーンボーナス・護符gained・コンボ倍率を計算しスコアへ加算 → **目標判定**
2. (既存)コンボ到達時の直接加算護符を適用 → **目標判定**
3. 場札除去後、全列が0枚(全消し)かどうかを判定
4. 全消しでなければ、通常のプレイ続行としてこれまで通り返す
5. 全消しなら: 全消しボーナスを加算 → **目標判定**
6. まだ終了していなければ、**共通処理「コンボリセット」**を実行(治癒はこの中で解決)
7. 護符を所持順(`items`配列の並び順)に処理する。**再生**については、6の時点で場札がまだ全消し状態(残り0枚)であり、かつ`regenerationUsedThisWave`が`false`であり、かつ**山札が1枚以上残っている**場合のみ発動する。発動条件を満たせば、スコアの50%を消費して捨て札から場札全体を復活させ(現行の再配布ロジックを踏襲)、`regenerationUsedThisWave`を`true`にする。治癒が先に(所持順で)列を埋めていれば、この時点で全消し状態ではなくなっているため再生は発動しない
8. 7の結果、場札が(治癒または再生によって)復活していれば: `drawStock`と全く同じロジックで山札を1枚めくる(山札が0枚の場合は何もしない)。ウェーブは`playing`のまま継続する
9. 7の結果、場札が復活していなければ(治癒も再生も発動しなかった、または山札が0枚で再生が発動条件を満たさなかった): 通常の全消し終了(`status: 'ended', endReason: 'fullClear'`)とする

## 5. 手詰まり時のフロー(`applyStuckCheck`相当)

1. 手詰まり判定(山札0枚・場札はあるが取れる列がない)
2. 手詰まりなら、**共通処理「コンボリセット」**を実行(治癒はこの中で解決)
3. 護符を所持順に処理する。**不屈**については、`discardPile`が1枚以上あり、かつ`resilienceUsedThisWave`が`false`の場合のみ発動する。発動条件を満たせば、スコアの30%を消費して捨て札の半数(現行通り`Math.ceil(pool.length / 2)`)を山札へ戻し、`resilienceUsedThisWave`を`true`にする
4. 3の結果、山札に1枚以上戻っていれば: `drawStock`と全く同じロジックで山札を1枚めくる。ウェーブは継続する
5. 3の結果、山札が戻っていなければ(不屈が発動しなかった): 通常の手詰まり終了(`status: 'ended', endReason: 'stuck'`)とする

## 6. 「山札を捲る」の実装方針とAPIへの影響

全消し・手詰まり後の自動めくりは、通常の`drawStock`と完全に同じロジックを呼び出す(素朴・促束・静寂・誠実など他の護符の効果もすべて従来通り発動する)。これに伴い、以下のシグネチャ変更が必要になる。

- `playCard`: `deckComposition`を追加引数に取り、戻り値を`{ wave: WaveState; deckComposition: DeckCard[] }`に変更する
- `applyPlayCard`: 内部で`playCard`に`run.deckComposition`を渡し、返ってきた`deckComposition`を`RunState`に反映する(`applyDrawStock`と同じパターン)
- `applyStuckCheck`: 内部で不屈発動後に`drawStock`を呼べるよう、同様に`deckComposition`を読み書きする

**影響を受ける呼び出し元:**
- `src/routes/game/shidasu/+page.svelte`(`applyPlayCard`経由のため実質変更不要)
- `src/routes/admin/shidasu-debug/+page.svelte`(`playCard`を直接呼んでいるため、`deckComposition`受け渡しコードの追加が必要。既存の`drawStock`呼び出しと同じパターンに揃える)

## 7. スコープ外

- 直感の変更(既存実装で要件を満たしていることを確認済み。変更不要)
- `regeneration.p`・`resilience.p`の数値変更(50%・30%のまま)
- 治癒・再生・不屈以外の護符の効果変更

## 8. 受け入れ基準

1. 治癒が、通常のコンボリセット(drawStockのパターン不継続)・全消し・手詰まりのいずれでも、そのコンボ中に列一掃した列を(コンボ開始時の枚数を上限に)捨て札から復活させる
2. 再生が、山札が残っている全消し時にのみ発動し、コンボリセット+チェーンの捨て札行きの後、所持順で治癒より後で解決され、スコア50%消費で場札を復活させ、その後山札を1枚捲る。ウェーブ中2回目以降は発動しない
3. 不屈が、手詰まり時にコンボリセット+チェーンの捨て札行きの後、所持順で治癒より後で解決され、スコア30%消費で捨て札の半数を山札に戻し、その後山札を1枚捲る。ウェーブ中2回目以降は発動しない
4. 治癒が先に列を埋めたことで全消し状態でなくなった場合、再生は発動しない
5. 目標スコアはスコアが変動するたびに判定され、達成した時点で以降の得点計算・全消し処理・コンボリセット処理は行われずウェーブが終了する
6. `playCard`・`applyPlayCard`・`applyStuckCheck`のシグネチャ変更が全呼び出し元(`game/shidasu`・`admin/shidasu-debug`)に反映され、ビルド・型チェックが通る
7. 既存のテストで挙動が変わる箇所は、新仕様に合わせてテストを更新する。それ以外の護符の挙動に影響がないことを既存テストで確認する
8. `npm run test`・`npm run check`・`npm run build`が成功する
