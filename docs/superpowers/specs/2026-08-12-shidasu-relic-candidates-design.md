# レリック個別候補(第1弾) 設計書

> 対象: `docs/shidasu/shidasu-roadmap.md` 項目5「レリックの実装」のうち、システムの仕組み(`docs/superpowers/specs/2026-08-12-shidasu-relic-system-design.md`)は実装済み。本ドキュメントは個別レリックの効果候補(仮称含む)をまとめる。

## 背景・目的

レリックシステム自体は先行セッションで実装済み(動作確認用の`placeholder`のみを保持)。本セッションでは、roadmap項目5に例示された4方向性(ショップ価格減少・商品提示数増加・リロールコスト減少・秘儀天啓神託の所持上限増加)を中心に、それ以外のメタ/経済効果も含めて幅広く候補を検討し、13個を採用した。

## 方針

- **対象範囲**: レリックは「護符の守備範囲外(ゲームプレイに直接かかわる部分以外)で有利になる効果」という既存の定義を厳守する。ショップ・所持上限・通貨などラン運営面の効果のみを対象とし、場札・デッキ構成・スコア計算など既存の護符・秘儀・天啓・神託の守備範囲と重複する効果は候補から除外する(検討過程で「場札の配布行数+n」が既存の護符「暗雲」・天啓「虚」(`extraTableauRows`)と機能重複することが判明し、除外・保留とした。詳細は下記「保留・不採用の記録」参照)。
- **報酬追加系は必ずプレイ内容条件付きにする**: `docs/shidasu/shidasu-roadmap.md`項目3(報酬の計算方法の検討)で「プレイ内容関連の報酬はレリックで実装する」と決めた方針を反映し、Waveクリア時に追加報酬を得るタイプの候補はすべて、固定額加算ではなくそのWave中のプレイ内容(コンボ数・役の成立種類数・山札消費割合など)に応じた変動報酬にする。
- **数値はすべて変数化し管理画面から編集可能にする**: 既存の秘儀・天啓・護符と同様、効果に使う数値は`params.relics[id]`内の個別フィールド(`n`・`tsukumokaN`など)として持たせ、将来`/admin/shidasu-relics`(新設予定)から編集できるようにする。本specでは変数名と初期値の方向性までを決め、未確定のものは実装時に決定する。
- **付喪化(進化)後は効果を強化する**: 既存の仕組み(`RunState.relics[].tsukumoka`)通り、付喪化後は初期効果と同じ対象のまま数値が強化される、または初期効果に対象が追加される形にする(候補ごとに個別記載)。
- **名前はすべて仮称**: 置物・郷土玩具・縁起物のモチーフに沿った日本語名を仮でつけている。実装確定時に見直してよい。

## 採用した13候補

| 仮称 | 効果概要 | 変数 |
|---|---|---|
| 招き猫 | ショップの全商品(護符・秘儀・天啓・神託のバラ売り、福袋2枠、レリック専用枠)の購入価格を一律値引き | `discountPercent`(初期25) / 付喪化後`tsukumokaDiscountPercent`(初期50)に強化 |
| 福だるま | ショップのリロールコスト刻み幅(`rerollCostStep`)を`n`だけ減らす | `n`(未定) / 付喪化後、上記効果に加えて同一ショップ訪問中の最初の1回のリロールコストを0にする |
| 熊手 | バラ売り枠を`n`枚増やす | `n`(未定) / 付喪化後、上記効果に加えて福袋枠も`n`枠増やす |
| 五円玉 | Waveクリア時、そのWaveでの最大コンボ数に応じて追加報酬(`floor(maxComboThisWave / 5) × n`)を得る | `n`(未定) / 付喪化後、`n`をより大きい値に強化 |
| 招き布袋像 | 護符の所持上限を`n`増やす | `n`(未定) / 付喪化後、さらに`tsukumokaN`増やす |
| 破魔矢 | 秘儀の所持上限を`n`増やす | `n`(未定) / 付喪化後、さらに`tsukumokaN`増やす |
| 千羽鶴 | 天啓・神託(合算)の所持上限を`n`増やす | `n`(未定) / 付喪化後、さらに`tsukumokaN`増やす |
| 福笹 | 福袋の枠を`n`枠増やす(熊手と逆順の対) | `n`(未定) / 付喪化後、上記効果に加えてバラ売り枠も`n`枚増やす |
| 開運こけし | 護符・秘儀・天啓・神託の売却価格を一律上乗せ | `sellBonusPercent`(初期25) / 付喪化後`tsukumokaSellBonusPercent`(初期50)に強化 |
| 縁起小槌 | 福袋の選択肢数(`offerCount`)を全ジャンル`n`増やす | `n`(未定) / 付喪化後、さらに`tsukumokaN`増やす |
| 縁起鈴 | レリック専用枠の提示数を`n`増やす(既定1、通常1個→2個) | `n`(初期1) / 付喪化後、さらに`tsukumokaN`(初期1)増やす(→3個) |
| 貯金箱 | Waveクリア時、そのWaveで成立した役の種類数(distinct)に応じて追加報酬(`floor(成立した役の種類数 / 2) × n`)を得る | `n`(初期1) / 付喪化後、`n=2`に強化 |
| 招き犬 | Waveクリア時、山札の消費割合に応じて追加報酬を得る。`a`=クリア時点の山札残り枚数、`b`=場札の初期配布枚数、`c`=デッキの総枚数として`floor(((c - b - a) / (c - b)) × n)` | `n`(初期5) / 付喪化後、`n=10`に強化 |

## 保留・不採用の記録

| 元候補 | 内容 | 判定 | 理由 |
|---|---|---|---|
| 独楽 | Wave開始時、場札に配る行数を`n`増やす | 保留 | 既存の護符「暗雲」・天啓「虚」が同じ`extraTableauRows`の仕組みを使っており、単機能アイテムであるこの2つを今削除すると効果が空になってしまう。暗雲・虚をどう扱うか(削除/再設計)は別セッションで検討したうえで、改めてレリック化を検討する |
| 商売繁盛の看板 | 護符の売却価格のみ+30%(付喪化+50%) | 不採用 | 採用済みの「開運こけし」(護符・秘儀・天啓・神託すべての売却価格アップ)の下位互換になるため |
| 盛り塩 | ショップのバラ売り枠抽選で、所持中の秘儀・天啓・神託も護符と同様に重複除外する | 不採用 | 今回は見送り(明確な理由なく一旦不採用) |

## 実装時の技術メモ(参考、詳細設計は別途プランで詰める)

- **価格系(招き猫)**: `itemBuyPrice`/`riteBuyPrice`/`revelationBuyPrice`/`oracleBuyPrice`/`relicBuyPrice`各関数、および福袋(`ShopPackSlot.price`、`rollPackSlots`でカタログからスナップショットされる価格)の両方に倍率を適用する必要がある。既存の護符とは異なりレリックは`run.relics`を参照する。
- **所持上限系(招き布袋像・破魔矢・千羽鶴)**: 現状ハードコードされている上限値(秘儀`>= 3`、天啓+神託`>= 2`、護符`items.maxItems`)を、所持レリックに応じて動的に加算する仕組みが必要。
- **Waveクリア報酬条件付き系(五円玉・貯金箱・招き犬)**: `resolveWaveEnd`の`earned`計算(現状は`currentStar?.reward ?? 0`のみ、2026-08-11に基礎報酬`waveClearAmount`を廃止済み)に、所持レリックによる追加報酬項を加える。
- **レリック専用枠の提示数(縁起鈴)**: 現状`ShopState.relic`は単一の`{ id, sold } | null`。提示数を増やす場合はこのフィールドを配列化する必要があり、既存の実装(先行セッションの`shop.ts`/`+page.svelte`)への影響が大きい。実装時に設計を再確認すること。
- **admin画面**: `/admin/shidasu-relics`は現状存在しない。個別レリックの実装と合わせて新設が必要。

## スコープ外

- 各候補の具体的な数値決定(未定`n`の実際の値)は実装計画(plan)作成時に決定する
- 付喪化のトリガーとなる天啓の設計・実装(先行specから継続してスコープ外)
- 護符「暗雲」・天啓「虚」の削除/再設計の検討(独楽の保留に伴う派生タスク、別セッション)
- 実装そのもの(本specはブレインストーミングの成果物であり、この後の実装計画(plan)作成・実装は別途進める)
