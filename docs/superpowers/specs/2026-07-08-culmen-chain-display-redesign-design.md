# Culmen チェーン表示の重ね表示化 + 山札由来アンカーの導入 設計

## 0. 背景・目的

現在、`/game/culmen`のプレイ画面下部には、現在のコンボで取った札(`wave.chain`)がフラットに横並びで表示されている。この表示を、山札から捲った札を基準に、場からプレイした札を少しずらして重ねる表示に変更し、「今どこから続いているコンボなのか」を視覚的にわかりやすくする。

あわせて、現状のエンジンでは「ウェーブ開始時に配られる最初の場札(foundation)」と「コンボが途切れた際に新しく捲った札」が`chain`に一切含まれておらず、この2つのタイミングで場からプレイした最初の1枚は必ずボーナス0(基礎点のみ)になっていた。今回、これらの札を`chain`の起点(1枚目)として明示的に組み込み、直後の場札プレイがこの起点とのパターン一致でボーナスを得られるようにする。

## 1. スコープ

- 対象: `src/lib/game/culmen/types.ts`(`WaveState`に`chainOrigin`追加)、`src/lib/game/culmen/engine.ts`(`startWave`・`drawStock`の変更)、`src/lib/game/culmen/engine.test.ts`(既存テストの更新)、`src/routes/game/culmen/+page.svelte`(チェーン表示部分の全面書き換え)
- 対象外:
  - 役の成立を示す「枠」表示(将来の別機能として保留。今回は実装しない)
  - `/admin/culmen`側の変更(新しいパラメータは追加しないため不要)
  - `evaluateChainBonus`・`chainContinuesPattern`・`analyzeSuitColor`・`analyzeStair`・各役判定関数(`checkFlush`等)自体のロジック変更(これらは`Card[]`を受け取って判定するだけで、内部ロジックの変更は不要。何が渡されるかが変わるだけ)

## 2. データモデルの変更

`WaveState`(`types.ts`)に新しいフィールドを追加する:

```ts
export type ChainCardOrigin = 'play' | 'draw'
```

`WaveState`に追加:
```ts
chainOrigin: ChainCardOrigin[]
```

`chain`と`chainOrigin`は常に同じ長さを保つ(`chain[i]`の由来が`chainOrigin[i]`)。`'play'`は場(タブロー)からプレイして取った札、`'draw'`は山札から捲った札を表す。

## 3. エンジンの変更(スコア計算に影響あり)

### 3.1 `startWave`

ウェーブ開始時に配られる最初の場札(`foundation`)を、`chain`の1枚目として組み込む。

変更前: `chain: [], `(コメント上の例。実際は`chain: []`のみ)
変更後: `chain: [foundation], chainOrigin: ['draw'],`

`combo`(0または`startCombo`)・`linked`(`false`)は変更しない。

### 3.2 `drawStock`

- ワイルド分岐: `chainOrigin`に`'draw'`を追記する(`chain`への追記と対にする)
- シールド/パターン継続分岐: 同様に`chainOrigin`に`'draw'`を追記する
- リセット分岐: 現状は`chain: []`(空)にリセットしていたが、`chain: [捲った札]`(その捲った札1枚だけを新しい起点とする)に変更する。`chainOrigin: ['draw']`も対応して設定する。`combo`(baseComboにリセット)・`linked`(`false`)・`columnsEmptiedThisCombo`(0)・`lastGain`(null)は変更しない。

### 3.3 `playCard`

`chain`に札を追記する箇所(`chain: [...wave.chain, card]`)に対応して、`chainOrigin: [...wave.chainOrigin, 'play']`を追記する。それ以外のロジック(`evaluateChainBonus`の呼び出し方法など)は変更しない。

### 3.4 この変更による実際のスコアへの影響

これまで、各ウェーブの最初の1枚、およびコンボがリセットされた直後の最初の1枚を場からプレイする際は、`wave.chain`が空(`[]`)だったため`evaluateChainBonus`が早期リターンし、必ずボーナス0(基礎点のみ)になっていた。

今回の変更により、`wave.chain`は常に最低1枚(直前の山札由来の起点)を保持するようになるため、その直後に場からプレイする最初の1枚は、この起点とスート・色・階段が一致していれば、通常通り同スートボーナス等が加算されるようになる。役判定(フラッシュ・ロイヤル・同ランク・コンプリートラン)も、この起点の札を「すでに取った札」の一部として数える。

一方、山札を連続して捲る際の「パターン継続」判定(`chainContinuesPattern`、`wave.linked`が前提条件)は変更しない。まだ場から1枚もプレイしていない状態(`linked: false`)でいきなり山札を捲っても、これまで通り必ずリセット扱いになる(起点の札1枚だけでは「継続中のパターン」とはみなさない、という原則を維持する)。

### 3.5 この変更で`chain`が空にならなくなることの確認

上記3.1〜3.3の結果、`wave.chain`は`status: 'playing'`の間、常に1枚以上を保持し続ける(空配列になることがなくなる)。これにより、UI側で「チェーンが空の場合」の分岐処理が不要になる(4節参照)。

## 4. 表示(UI)の変更

`src/routes/game/culmen/+page.svelte`の`playArea`スニペット内、現状のチェーン表示部分(フラットな横並び。「取った札がここに並ぶ→…」のプレースホルダー文言を含む)を、以下の仕様に全面的に置き換える。既存の実装は破棄してよい。

- `wave.chain`の全カードを、1本の連続した重なりとして表示する(区切り・グループ分けはしない)
- 各カード`chain[i]`は、コンテナ内で`left: i * 10px`の位置に絶対配置し、`z-index`を`i`の昇順(後の札ほど手前)にする
- 縦位置: `chainOrigin[i] === 'draw'`のカードは基準線(`top: 6px`)、`chainOrigin[i] === 'play'`のカードは少し上にずらした位置(`top: 0px`)に配置する(ブレインストーミングのモックアップで確認済みの値)
- 枠などの追加装飾は付けない(将来の役成立演出は別機能として今回は実装しない)
- 3.5の通り`chain`が空になることはなくなるため、「チェーンが空の場合のプレースホルダー文言」の分岐は削除する

## 5. テストへの影響

`engine.test.ts`の既存テストのうち、以下が本変更の影響を受けるため更新が必要になる:

- `describe('startWave', ...)`の初期状態テスト: `wave.chain`が`[]`ではなく`[wave.foundation]`になることを検証するよう変更
- `describe('drawStock', ...)`のリセット系テスト(「通常時(継続条件なし)」「パターンに合わずシールドも無ければ通常通りリセットする」「コンボがbaseCombo以下ならシールドがあっても消費せずリセットする」): `next.chain`が`[]`ではなく`[捲った札]`になることを検証するよう変更
- `playCard`側のテストは、`makeWave`ヘルパー経由で任意の`WaveState`を直接組み立てているため(`startWave`を経由しない)、本変更の影響を受けない。ただし`makeWave`のデフォルト値に`chainOrigin: []`を追加する必要がある(型を満たすため)
- 新規: `chainOrigin`が`chain`と対になって正しく更新されることを検証するテストを、`playCard`・`drawStock`それぞれに追加する

## 6. 受け入れ基準

1. ウェーブ開始直後、`wave.chain`が`[foundation]`(1枚)、`wave.chainOrigin`が`['draw']`になっている
2. ウェーブ開始直後、場から1枚目をプレイした際、foundationとスート/色/階段が一致していれば対応するボーナスが加算される
3. まだ場から1枚もプレイしていない状態で山札を捲った場合、これまで通り必ずリセット扱いになる(パターン継続にならない)
4. コンボが途切れて山札をリセット扱いで捲った場合、`wave.chain`がその捲った札1枚だけになる(空配列にはならない)
5. `/game/culmen`のチェーン表示が、全カード1本の重なりとして表示され、山札由来の札は基準線、場からプレイした札は少し上にずれて表示される
6. 表示上、区切り線やグループ分けは無く、連続した重なりとして見える
7. `npm run test`・`npm run build`が成功する
