# Shidasu デバッグ専用サンドボックス画面の設計

## 0. 背景・目的

`docs/shidasu-roadmap.md`に「現在は`DebugPanel.svelte`(開発時のみ表示)で内部状態表示・山札の次を強制指定ができるが、護符の効果検証やステージ/ウェーブの任意設定など、開発時の検証をより効率化するための専用画面(または現行パネルの拡張)を検討する」という残タスクがある。本specは、このうち「護符の効果検証」に的を絞り、`/admin`配下に専用のデバッグサンドボックス画面を新設する設計を定める。

対象範囲はShidasu専用とする(他ゲームへの汎用化は将来必要になった時点で検討する)。

## 1. 全体アーキテクチャ

**ルート**: `src/routes/admin/shidasu-debug/+page.svelte`(新規)

**方式**: `/game/shidasu`の実プレイセッションとは完全に独立したサンドボックス。既存の`startWave`・`playCard`・`drawStock`(`$lib/game/shidasu/engine.ts`の純粋関数)をそのまま呼び出し、ページコンポーネントのローカルstate(Svelte 5 runes)だけで完結させる。永続化・タブ間連携・実プレイセッションとの連動は行わない。

**画面構成**(PC前提、画面幅を最大限使用):

1. **盤面パネル**: `startWave`で通常プレイと同じ見た目でウェーブを配る。場札・山札・チェーンを表示し、通常プレイ同様に場札クリックでプレイ・山札クリックでめくりができる(編集後の実際の得点計算をその場で確認するため)。
2. **カードパレット**: 全52種の実カード(4スート×13ランク)+ワイルドの計53種をグリッド表示。ここから盤面(場札の任意の1枚、山札の先頭)へドラッグすると、そのカードを入れ替える。
3. **護符チェックリスト**: 87種類を`docs/shidasu-gofu-candidates.md`のグループ分けに沿って一覧表示し、チェックボックスで所持・非所持を即座に切り替え。各項目に`itemDesc`ベースの簡潔な説明文を添える。
4. **内部状態パネル(DebugStatePanel)**: 既存`DebugPanel.svelte`の内容を拡張して表示(詳細は4節)。
5. **「新しいウェーブ」ボタン**: 現在選択中の護符構成を保持したまま、盤面を再度配り直す(`startWave`を新しいシードで再実行)。

ステージ修飾子(none/noLoop/faceLock)は常に`none`固定とし、切り替えUIはスコープ外とする。

## 2. ファイル構成

- `src/routes/admin/shidasu-debug/+page.svelte`(新規): ページ全体のレイアウト・state管理(`items`・`wave`・`deckComposition`・`lastSwap`)。既存の`/game/shidasu/+page.svelte`のプレイ操作ロジックを参考に流用する。
- `src/routes/admin/shidasu-debug/CardPalette.svelte`(新規): 53種のカード一覧をドラッグ元として表示するコンポーネント。
- `src/routes/admin/shidasu-debug/ItemChecklist.svelte`(新規): 87護符のグループ別チェックリスト。
- `src/routes/admin/shidasu-debug/DebugStatePanel.svelte`(新規): 内部状態表示コンポーネント(4節の内容)。
- `src/routes/admin/+page.svelte`(既存を修正): 一覧に本ページへのリンクを追加。

既存の`src/routes/game/shidasu/DebugPanel.svelte`(実プレイ画面側)は変更しない(「山札の次を強制指定」フォームが本サンドボックスのカード入れ替え機能と役割が重複するが、実プレイ側は現状維持とする)。

## 3. カード入れ替えの実装方針

**ドラッグ&ドロップ**: `src/routes/game/solitaire/+page.svelte`で実績のある、ポインターイベントベースの自前ドラッグ実装を踏襲する。標準のHTML5 Drag and Drop APIは使わない。

- `pointerdown`でドラッグ開始(ドラッグ元のカード情報を保持する`dragInfo`相当のstateを新設)
- `pointermove`で追従する浮遊表示(絶対配置の要素をカーソル位置に追従させる)
- `pointerup`でドロップ先を座標から判定し、入れ替えを実行

**盤面カードへのドロップ**: 場札の任意の1枚(先頭に限らずスタック内の任意の位置)にドロップすると、その`Card`オブジェクトの`suit`/`rank`/`wild`をドラッグ元の値で上書きする(`id`は維持してSvelteのキー管理を壊さない)。列・行をインデックスで特定し、`tableau[colIndex][rowIndex]`を直接更新する、このページ内のローカル関数で行う(`engine.ts`は変更しない)。

**山札先頭へのドロップ**: `wave.stock[wave.stock.length - 1]`(次にめくられる位置)を同様に上書きする。

**元に戻す(1回限りのUndo)**: 直前のカード入れ替え1件だけを`lastSwap: { location: { col: number; row: number } | 'stockTop'; previousCard: Card } | null`としてローカルstateに保持する(`location`は場札の場合`{ col, row }`で列・行を指定、山札先頭の場合は`'stockTop'`)。

- 入れ替えのたびに`lastSwap`を上書きする
- それ以外の操作(プレイ・山札めくり・護符の付与/削除・新しいウェーブ)が発生した時点で`lastSwap`を`null`にクリアする
- 「元に戻す」ボタンは`lastSwap`が非nullの間だけ有効化され、押すと該当位置のカードを`previousCard`に戻し`lastSwap`を`null`にする

## 4. 内部状態パネル(DebugStatePanel)の内容

既存`DebugPanel.svelte`の表示項目をベースに、以下を表示する:

- コンボ・列一掃基準長(`comboStreakColumnLengths`)・列一掃済み数・山札めくり演出(`lastDrawEffect`)
- 同スート/同色/階段の現在の成立状況(`analyzeSuitColor`/`analyzeStair`)
- チェーンの中身(カード一覧)
- 獲得点ログ(直近20件、内訳付き)
- 現在所持中の護符一覧(名前のみ、チェックリストと二重管理にならないよう読み取り専用の確認表示)
- ウェーブの状態(`status`/`endReason`)・スコア・山札残り枚数

## 5. 護符の付与・削除

チェックボックスのON/OFFで、ローカルの`items: ItemId[]`配列に対して単純な追加・削除を行う(`ITEM_POOL`のような抽選ロジックは使わない、直接指定)。1種類につき複数所持は不要(既存ゲームの「1種類につき最大1個まで」ルールに合わせる)。

## 6. スコープ外

- ステージ/ウェーブの任意ジャンプ、スコア/コンボの直接書き換え(将来の別タスク)
- ステージ修飾子の切り替え
- 状態の保存・共有・実プレイセッションとの連動
- 複数手順のUndo履歴(直前1件のみ)
- 他ゲーム(solitaire等)への汎用化

## 7. 受け入れ基準

1. `/admin`から本ページへ遷移でき、`startWave`による通常のウェーブが表示される
2. カードパレットから場札の任意のカード(スタック内の任意位置を含む)へドラッグすると、そのカードが入れ替わる
3. カードパレットから山札の先頭へドラッグすると、次にめくられるカードが入れ替わる
4. 入れ替え直後は「元に戻す」ボタンが有効化され、押すと直前の入れ替えのみが取り消される
5. 入れ替え後にプレイ・山札めくり・護符の付与/削除・新しいウェーブのいずれかを行うと、「元に戻す」ボタンは無効化される
6. 護符チェックリストのチェックを切り替えると、即座に所持護符が変わり、以降のプレイ結果に反映される
7. 内部状態パネルに、コンボ・チェーン・獲得点ログ・所持護符・ウェーブ状態が表示される
8. 「新しいウェーブ」ボタンで、護符構成を保持したまま盤面が再度配られる
9. `npm run test`・`npm run build`・`npm run check`が成功する
