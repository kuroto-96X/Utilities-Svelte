# Shidasu ステージ構成(ボスウェーブ)導入 設計 — Phase 1

## 0. 背景・目的

`docs/shidasu/shidasu-roadmap.md`項目4「ステージ構成の検討」で構想されていた、小ボス・中ボス・大ボスを軸としたステージ構成を実装する。ロードマップの構想メモは以下の複数の独立したサブシステムを含んでいたため、フェーズに分割する:

- **Phase 1(今回)**: 9ウェーブ(3ステージ×3ウェーブ)構成のコア変更。ボス階級ごとの制約は各1種類固定。「ラン」は特殊ルール無しの単一構成。大ボスクリア後は継続可否を選べる(スコアアタック)
- Phase 2(後日): ボス制約の複数候補化・ランダム選出
- Phase 3(後日): 「ラン」の複数選択・ラン固有の特殊ルール
- Phase 4(後日、ロードマップ項目5のゲーム内通貨実装後): ボスクリア時の特別報酬

本ドキュメントはPhase 1のみを対象とする。

## 1. 全体構造・命名

- 既存の3ステージ×3ウェーブ構造(`RunState.stageIndex`・`waveIndex`)をそのまま活用する。`stageIndex`は**上限なく増加**し続け、`stageIndex % 3`でそのステージのボス階級を決定する(0=小凶、1=中凶、2=大凶)。3ステージ(9ウェーブ)ごとに小凶→中凶→大凶のサイクルを無限に繰り返す
- 各ステージの1・2ウェーブ目は常に制約なし(`none`)。3ウェーブ目のみ、そのステージの階級に対応するボス制約を適用する
- ボス階級名は「小凶(しょうきょう)・中凶(ちゅうきょう)・大凶(たいきょう)」とする。おみくじの凶グレードから、星詠み(占い)の世界観に合わせて採用した

## 2. ボス制約の仕様(各階級1種類固定)

| 階級 | 制約名(仮) | 挙動 |
|---|---|---|
| 小凶 | A⇔Kループ禁止 | 既存の`noLoop`修飾子をそのまま流用する(ランク差12での接続を禁止) |
| 中凶 | 2コンボ以下で無得点(n=2、仮数値) | カードは通常通り取れる(プレイ自体は制限しない)が、そのプレイの`effectiveCombo`が2以下であれば、そのプレイで得られるはずの獲得点(基礎点・チェーンボーナス・列一掃ボーナス等を含めた総額)を0にする。コンボ数自体は通常通り進行する |
| 大凶 | 特定スートで無得点 | 中凶ステージクリア直後(=大凶ステージの1ウェーブ目を配る時点)に、既存の`rand`(シード連動PRNG)を使って♠♥♦♣からランダムに1つ選び、`RunState`に保持する。以後そのステージが終わるまで(1〜3ウェーブ目全て)固定で使い回す。そのウェーブ中、対象スートの非ワイルドカードを取ったプレイは獲得点を0にする(ワイルドは対象外、通常通り得点する) |

- `faceLock`(絵札制限)は今回の3階級には割り当てない(Phase 2でボス制約候補プールに戻す余地を残す)
- 中凶・大凶は「取得自体は妨げない、得点だけ0にする」という新しい制約の型であり、既存の`StageModifier`(`isPlayable`の可否判定に使う、取得を禁止する型)とは別の仕組みとして実装する(詳細な型・関数構成は実装プランで検討する)
- 大凶の対象スート抽選に`Math.random()`を直接使わず、既存の`rand`引数(`beginRun`のシードから連鎖する既存のPRNGの仕組み)を必ず経由すること。将来「ラン開始時にシードを指定してステージ構成を再現する」機能を追加する際、この経路を通っていないとシードを固定しても大凶の対象スートだけ再現できなくなるため

## 3. 目標スコア算出式

```
target(n) = 2000 × 1.5^(n-1)
```

- `n`はラン開始からの通しウェーブ番号(1始まり)。ステージ・サイクルをまたいで際限なく上昇し続ける
- 端数は`Math.floor`で切り捨てる
- 基礎点2000・倍率1.5は仮の初期値。最終的なバランス調整は別途行う

## 4. フェーズ遷移の変更

- 既存の`stageClear`フェーズ(小凶・中凶クリア時に、護符等の選択をスキップして次の制約だけ見せる画面)は**廃止**する。小凶・中凶クリア時も、他の通常ウェーブと全く同じく`itemSelect`→`revelationSelect`→`oracleSelect`を経て次のウェーブへ進む
  - これは一時的な措置である。今後ロードマップ項目5(ゲーム内通貨・ショップ)を実装した際、ウェーブクリアごとに通貨を獲得してショップへ移動する形に置き換える予定
- 大凶(各サイクルの9ウェーブ目、`stageIndex % 3 === 2`のステージの3ウェーブ目)クリア時のみ特別に、新設フェーズ`continueChoice`へ遷移する
  - 「続ける」を選ぶと、通常通り`itemSelect`→`revelationSelect`→`oracleSelect`を経て次のサイクル(次の小凶ステージ)へ進む。所持中の護符・秘儀・天啓・神託レベルは全て引き継がれ、リセットされない
  - 「やめる」を選ぶと結果画面へ遷移する(既存`allClear`フェーズ・画面を改称・再利用する)
- 目標スコア未達時の`gameOver`遷移は変更なし
- `advanceStage`関数(旧stageClear→次ステージ遷移専用)は廃止し、ステージをまたぐ遷移も通常のウェーブ進行(`pickItem`/`skipItemSelect`等が担う`waveIndex`・`stageIndex`更新)に統合する

## 5. RunStateの変更点

- `stageIndex`: 既存のまま。ただし上限チェック(`stages.length - 1`で止める処理)を撤廃し、無制限に増加させる
- ステージ内3ウェーブ目(ボスウェーブ)クリア時、`waveIndex`を0に戻すと同時に`stageIndex`を+1する(現在「ウェーブ3クリア→次ステージへ」という特別遷移だったものを、通常の`waveIndex`更新処理に統合する。大凶ステージの3ウェーブ目クリアだけは前述の通り`continueChoice`を経由する点が異なる)
- 新規フィールド: 大凶ステージの対象スートを保持する(例: `currentGreatMisfortuneSuit: Suit | null`。ステージが小凶・中凶の間は`null`、大凶ステージに入るタイミングで確定した値をセットする)
- `params.stages`(現行、`name`・`modifier`・`targets`を持つ固定3要素配列)は、ボス階級ごとの制約定義(3要素、`stageIndex % 3`でインデックス)+目標スコア算出式のパラメータ(基礎点・倍率)に置き換わる。具体的なデータ構造は実装プランで設計する

## 6. UI表示の変更

- 常時表示エリア(現行`stageRow`スニペット、STAGE番号+制約ラベルの表示箇所)を「次のボス情報」表示に差し替える
  - 非ボスウェーブ中: そのサイクルのボス階級名+制約内容を表示する(例:「次: 小凶(A⇔Kループ禁止)」)
  - 大凶ステージ中(1〜3ウェーブ目)は確定済みの対象スートも含めて表示する(例:「次: 大凶(♠で無得点)」)
  - ボスウェーブ自体をプレイ中は、進行中の制約であることが分かるよう強調表示に変える(例:「大凶(♠で無得点)」)
- `continueChoice`画面: 「続ける」「やめる」の2択のみのシンプルな全画面モーダル(既存の`stageClear`/`allClear`画面と同様のスタイル)

## 7. スコープ外(Phase 2以降で扱う)

- ボス階級ごとの制約候補の複数化・ランダム選出、次のボスの制約が「わかるように」なる演出(候補が複数になって初めて意味を持つ)
- 「ラン」の複数選択・ラン固有の特殊ルール
- ボスクリア時の特別報酬(ゲーム内通貨)
- ラン開始時のシード指定によるステージ構成再現機能そのもの(今回は大凶スート抽選を`rand`経由にすることで将来の対応余地だけ残す)

## 8. 受け入れ基準

1. 各ステージの1・2ウェーブ目は制約なしでプレイでき、3ウェーブ目のみそのステージの階級(小凶/中凶/大凶、`stageIndex % 3`で決定)に対応する制約が適用される
2. 小凶ステージの3ウェーブ目は、既存のA⇔Kループ禁止と同じ挙動になる
3. 中凶ステージの3ウェーブ目は、2コンボ以下のプレイで獲得点が0になる(コンボ数自体は進む)。3コンボ以上のプレイは通常通り得点する
4. 大凶ステージに入った時点(1ウェーブ目を配る時点)で対象スートが1つランダムに決まり、常時表示エリアに反映される。3ウェーブ目まで同じスートが使われ続ける。対象スートの非ワイルドカードを取ると獲得点が0になり、ワイルドや他スートは通常通り得点する
5. 小凶・中凶ステージの3ウェーブ目クリア時も、他のウェーブと同様に護符→天啓→神託の選択画面を経て次のウェーブへ進む(旧stageClear画面は表示されない)
6. 大凶ステージの3ウェーブ目(9ウェーブ目)クリア時、「続ける/やめる」の選択画面が表示される。「続ける」を選ぶと護符→天啓→神託の選択画面を経て次のサイクル(小凶ステージ)へ進み、所持品・神託レベルは維持される。「やめる」を選ぶと結果画面が表示される
7. 目標スコアは`2000 × 1.5^(n-1)`(nは通しウェーブ番号)で算出され、ウェーブが進むごとに際限なく上昇する
8. 既存のテスト・機能(護符・秘儀・天啓・神託、通常ウェーブの得点計算等)に回帰がない
