# Shidasu 「スプレッド」(ラン選択)導入 設計 — Phase 3

## 0. 背景・目的

`docs/shidasu/shidasu-roadmap.md`項目4「ステージ構成の検討」で構想されていた、複数の「ラン」から選んでプレイする機能を実装する。ロードマップの構想メモは以下のフェーズに分割して進めており、今回はPhase 3を対象とする。

- Phase 1(実装済み): 9ウェーブ(3ステージ×3ウェーブ)構成のコア変更。ボス階級ごとの制約は各1種類固定。大凶クリア後は継続可否を選べる(スコアアタック)
- Phase 2(未着手): ボス制約の複数候補化・ランダム選出
- **Phase 3(今回)**: 「ラン」の複数選択・ラン固有の特殊ルール
- Phase 4(未着手、ロードマップ項目5のゲーム内通貨実装後): ボスクリア時の特別報酬

本ドキュメントはPhase 3のみを対象とする。アンロック(クリアで新しい選択肢が解放される進行度)の仕組みは今回のスコープ外とし、選択可能な項目は常に全て選べる状態とする。

## 1. 用語

「ラン」(1回のプレイ単位。タイトル画面から開始し、ゲームオーバーまたはやめるまでの一連のプレイ)と、プレイヤーが開始時に選ぶ固有ルールセットを区別するため、後者を**「スプレッド」**と呼ぶ。タロット占いにおける「特定のカード配置による占術の方式」を指す実在の用語であり、星詠み(占い)をテーマとする本作の世界観、およびソリティア自体の「場札の配置(tableau/spread)」という語感の両方に合致する。

スプレッドの命名モチーフは大アルカナ(タロットの22枚の切り札)から取る。既存の命名体系(秘儀=ルーン文字、天啓=二十八宿、神託=役名、護符=天候・徳目)に並ぶ新しい体系となる。

## 2. 今回実装するスプレッド(2種類)

| スプレッドID | 名前 | 特殊ルール | 説明文(仮) |
|---|---|---|---|
| `fool` | 愚者 | なし(現行Phase 1の挙動そのもの) | 特殊ルールなし |
| `moon` | 月 | 場札が常に1行少ない状態で始まる | 場札は常に1行少ない状態で始まる(護符・天啓による行数変動は通常通り発生する) |

- 「愚者」は大アルカナ0番、「何も背負わない標準的な始まり」を象徴する基本スプレッドとして採用
- 「月」は幻惑・視界が隠されるという意味合いが「場札が見えにくくなる(1行少ない)」効果と合致するため採用
- 「月」の目標スコア算出式(基礎値・倍率)は「愚者」と全く同じ値にする(場札が少ない分の難易度上昇は、目標スコア側の調整では相殺しない)
- 将来的にスプレッドを追加する余地を残すため、データ構造自体は3つ目以降を追加できる形にするが、今回のスコープでは2種類のみを実装する

## 3. データモデル

`ShidasuParams`に新規`spreads`セクションを追加する。

```ts
type SpreadId = 'fool' | 'moon'

interface ShidasuParams {
  // ...
  spreads: {
    fool: { name: string; desc: string; initialExtraTableauRows: number; waveTargetBase: number; waveTargetMultiplier: number }
    moon: { name: string; desc: string; initialExtraTableauRows: number; waveTargetBase: number; waveTargetMultiplier: number }
  }
}
```

現状`scoring.waveTargetBase`/`scoring.waveTargetMultiplier`(Phase 1で追加、全ラン共通のグローバル値)は、スプレッドごとに異なる値を持つべきデータのため、`scoring`から削除し`spreads`側の各エントリに移動する。

初期値:
```
fool: { name: '愚者', desc: '特殊ルールなし', initialExtraTableauRows: 0, waveTargetBase: 2000, waveTargetMultiplier: 1.5 }
moon: { name: '月', desc: '場札は常に1行少ない状態で始まる(護符・天啓による行数変動は通常通り発生する)', initialExtraTableauRows: -1, waveTargetBase: 2000, waveTargetMultiplier: 1.5 }
```

`RunState`に`spreadId: SpreadId`フィールドを追加する。`createInitialRun()`(タイトル画面の初期状態)は既定値として`'fool'`を入れておく(実際にゲームプレイへ反映されるのは`beginRun`以降のため、タイトル画面時点の値は意味を持たない)。

## 4. ロジックの変更点

- `beginRun(params, spreadId, seed?)`のように、選択されたスプレッドIDを受け取るよう変更する
- `run.extraTableauRows`の初期値は、現状ハードコードされた`0`ではなく`params.spreads[spreadId].initialExtraTableauRows`から取る
- `waveTarget()`関数は、`params.scoring.waveTargetBase/Multiplier`ではなく`params.spreads[run.spreadId].waveTargetBase/Multiplier`を参照するように変更する
- 護符(暗雲)・天啓(虚)による`extraTableauRows`の加算処理(既存ロジック)は変更しない。「月」スプレッドは初期値が`-1`であるだけで、以降の加算は通常のラン(愚者)と全く同じように働く。したがって「月」で暗雲護符を1つ持てば`-1+r`、虚を使えば`-1+r+n`のように、常に「愚者で得られるはずの行数から1引いた値」になる
- `params.layout.rows`(5)に対し`extraTableauRows`の最小値は`-1`(月の初期値のみ、加算はあっても減算はされない)なので、実際に配られる行数が0以下になることはない

## 5. UIの変更点

### タイトル画面
現行の「はじめる」単一ボタンを、スプレッドの一覧(現時点では「愚者」「月」の2枚)に差し替える。各項目に名前と説明文(`desc`)を表示し、選択すると`beginRun(params, spreadId)`でそのままゲームを開始する。

アンロック機構は今回実装しないため、常に両方の項目が選択可能な状態で表示される。

### プレイ中の常時表示
常時表示エリア(`stageRow`スニペット、現在は次ウェーブ/ボス情報を表示している行)の先頭に、現在プレイ中のスプレッド名を小さく追加表示する(例:「月 | 次: 小凶(A⇔Kループ禁止)」)。

### 既存の「タイトルへ戻る」ボタンとの関係
今回のPhase 4準備作業(前回セッション)で実装済みの「タイトルへ戻る」ボタン(ゲームオーバー・結果画面)は、そのままこの新しいスプレッド選択画面に戻ることになる。次のランで別のスプレッドを選び直せるようになり、既存の実装と自然に噛み合う。

## 6. 管理画面

`/admin/shidasu`に新規`SpreadsSection.svelte`を追加する。`BossTiersSection.svelte`と同様の固定フォーム(愚者・月それぞれの名前・説明文・初期行数オフセット・目標スコア基礎値/倍率を編集する入力欄)とし、動的な追加・削除UIは今回作らない。

## 7. スコープ外(Phase 3の対象外)

- ランクリアによる新スプレッドのアンロック・進行度の永続化(localStorage等)
- 3つ目以降のスプレッドの追加
- 行数オフセット以外の種類の特殊ルール(スコア倍率変更など)
- スプレッドの動的な追加・削除に対応した管理画面UI

## 8. 受け入れ基準

1. タイトル画面に「愚者」「月」の2つのスプレッドが表示され、それぞれ選ぶと対応するスプレッドでランが開始される
2. 「月」を選んで開始したランでは、場札が`layout.rows - 1`行で配られる。以降のウェーブでも(ステージが進んでも)常に1行少ない状態が維持される
3. 「月」のランで暗雲護符・虚の天啓を獲得した場合、通常(愚者)と同じ加算量だけ行数が増える(常に愚者より1行少ない状態を維持する)
4. 「月」の目標スコアは「愚者」と全く同じ値になる(`2000 × 1.5^(n-1)`)
5. プレイ中の常時表示エリアに、現在のスプレッド名が表示される
6. `/admin/shidasu`で各スプレッドの名前・説明文・初期行数オフセット・目標スコア基礎値/倍率を編集できる
7. 既存のテスト・機能(護符・秘儀・天啓・神託、ボスサイクル等)に回帰がない
