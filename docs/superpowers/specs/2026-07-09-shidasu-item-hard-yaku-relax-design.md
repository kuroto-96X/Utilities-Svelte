# Shidasuのアイテム刷新: 難条件役の緩和護符(ロードマップ項目2)

## 0. 背景・目的

`docs/shidasu-roadmap.md`の項目2「アイテムなどの詳細な種類と効果の検討」に着手する。今回は「役ボーナス軸」のうち、**成立条件が構造的に厳しい役(階段・フラッシュ・ロイヤルセット・コンプリートラン・列一掃)の条件緩和**にテーマを絞る。

あわせて、既存の7個のアイテム(紅の目利き・宮廷の紋章・コンボシールド・厚めの山札・ワイルド★・助走・完全消去)を全て削除し、アイテム制度そのものを「1種類につき最大1個まで」というシンプルなルールに統一する。

役ボーナス軸のうち、今回対象にしなかった役(同スート・同色・同ランク)や、他の軸(コンボ軸・全消し軸・詰み救済軸)、「ワンパン軸」(少ない枚数で高得点)は今回のスコープ外とし、`docs/shidasu-roadmap.md`に追記して次回以降に検討する。

## 1. 既存アイテムの全削除

以下7個のアイテムを、名前・効果・関連する専用ロジックごと`engine.ts`/`types.ts`/`params.ts`から削除する。

| 削除するID | 名前 | 効果 |
|---|---|---|
| `red5` | 紅の目利き | ♥♦の基礎点+50 |
| `face10` | 宮廷の紋章 | J/Q/Kの基礎点+100 |
| `shield` | コンボシールド | 山札めくりのコンボリセットを毎ウェーブ1回無効 |
| `stock5` | 厚めの山札 | 山札+5枚 |
| `wild1` | ワイルド★ | 毎ウェーブ山札に★を1枚混入 |
| `start1` | 助走 | コンボが1からスタート |
| `clear300` | 完全消去 | 全消しボーナス+3000 |

削除に伴い、以下の専用ロジック・状態・パラメータも合わせて削除する(既存7個の効果を実現するためだけに存在していたコードのため)。

- `WaveState.shieldLeft`フィールドと、`drawStock`内の`canShieldProtect`判定(コンボシールド保護)
- `startWave`内のワイルドカード追加投入ロジック(`wildCount`/`wild1Count`)
- `startWave`内の山札追加投入ロジック(`extra`/`stock5Count`)
- コンボ初期値ロジック(`hasStart1`/`startCombo`) → コンボは常に`0`からスタートに統一する
- `playCard`内の全消し追加ボーナス(`items.includes('clear300')`)
- `DrawEffect`型の`'shield'`バリアント(`'wild' | 'pattern' | null`の3種類に縮小)
- `ShidasuParams.items`セクションの`redBonusValue`・`faceBonusValue`・`shieldChargesPerPick`・`extraStockCount`・`wildPerPick`・`startCombo`・`fullClearItemBonus`(後述の新パラメータに置き換え)
- `UNIQUE_ITEMS`という特別区分の仕組み(下記2節により全アイテムが同じ扱いになるため不要)

## 2. アイテム所持ルールの変更: 1種類につき最大1個

`rollItemOffer`のフィルタ条件を、「`UNIQUE_ITEMS`に含まれ、かつ既に持っている場合のみ除外」から「既に持っているアイテムは種類を問わず全て除外」に変更する。結果として、全アイテムが実質的に「1個まで」の扱いに統一される。

アイテム所持数の上限や、所持アイテムの入れ替え機能は今回のスコープ外とし、`docs/shidasu-roadmap.md`に将来の検討事項として追記する。

## 3. 基本ルール変更(アイテム不要、常に全員に適用)

### 3.1 階段の必要最小連続枚数を3→5に引き上げ

`scoring.stairMinLen`の既定値を、現行の`3`から`5`に変更する(`DEFAULT_PARAMS`・`shidasu.config.json`の両方)。階段が成立しにくくなる、即座に有効な難化。

### 3.2 ワイルドによる役穴埋め(フラッシュ・ロイヤルセット・コンプリートラン)

以下3つの役の判定に、「ワイルドカードが不足分を埋める」ロジックを追加する。

- **フラッシュ**(`checkFlush`): 判定対象の直近4枚(実カード+ワイルドを含む)にワイルドが含まれる場合、不足しているスートをワイルド1枚につき1つ埋めたものとして扱う
- **ロイヤルセット**(`checkRoyalSet`): 判定対象の直近3枚(実カード+ワイルドを含む)にワイルドが含まれる場合、不足するJ/Q/Kのうち1つをワイルド1枚につき1つ埋めたものとして扱う
- **コンプリートラン**(`checkCompleteRun`): チェーン内のワイルド1枚につき、未出現のランクを1つ埋めたものとして扱う(複数枚あれば複数分)

**重要な注記**: 現時点のゲームには、ワイルドカードを山札に供給する手段が(2節で述べた`wild1`アイテムの削除により)存在しない。そのため、この3つの緩和ルールは実装するものの、**当面は実際のプレイでは発動しない**(ワイルドカード自体が出現しないため)。将来、別の新規アイテムでワイルド供給が復活した際に機能する設計として、今回先行実装しておく。この点は既知の仕様であり、不具合ではない。

## 4. 新規護符アイテム(2個)

護符の名前は「◯◯の護符」の形式で統一し、◯◯部分には助詞を含まない単語(タロット大アルカナの徳目や、寛容・慈悲などの抽象語をモチーフにした単語)を当てる。

### 4.1 架橋の護符(id: `bridge`)

階段成立に必要な最小連続枚数を、3.1節の基本ルール(5枚)から`3`枚に緩和する。

- 新パラメータ: `items.stairRelaxedMinLen`(既定値`3`)
- 効果説明文: `階段成立に必要な最小連続枚数を5→3枚に緩和`

### 4.2 寛容の護符(id: `grace`)

**基本ルール(護符なし)**: 列一掃ボーナスは、対象の列の全カード(`params.layout.rows`枚、既定5枚)を、1回も途切れていない連続コンボの中で0枚にした場合にのみ加算される。コンボが一度でも途切れた列は、その後空にしても列一掃ボーナスの対象にならない。

**護符ありの緩和後**: 対象の列が、現在の連続コンボが始まった時点で残り`rows - columnSweepRelaxCards`枚(既定`rows=5`, `columnSweepRelaxCards=2`→残り3枚)以下であれば、列一掃ボーナスの対象にする。

- 新パラメータ: `items.columnSweepRelaxCards`(既定値`2`)
- 効果説明文: `列一掃ボーナスの条件を「列の全5枚を1コンボで空に」→「残り3枚から1コンボで空に」に緩和`

**実装メモ**: この判定のため、`WaveState`に新しいフィールド`comboStreakColumnLengths: number[]`(列ごとの「現在の連続コンボが始まった時点での残り枚数」)を追加する。

- ウェーブ開始時: 全列とも`rows`で初期化する
- コンボが基準値(常に`0`)にリセットされる瞬間(`drawStock`のパターン継続不成立時): その時点の各列の残り枚数でスナップショットを取り直す
- コンボが継続する間(通常のプレイ、パターン継続的中の引き)は更新しない
- `playCard`で列が空になった瞬間、`comboStreakColumnLengths[列番号]`が条件(護符なしなら`=== rows`、護符ありなら`<= rows - columnSweepRelaxCards`)を満たす場合のみ、列一掃ボーナスを加算し`columnsEmptiedThisCombo`をインクリメントする。満たさない場合はボーナス・カウンタともに変化なし。

## 5. アイテムプール構成

`ITEM_POOL`は`['bridge', 'grace']`の2個のみになる。ウェーブクリアのたびに最大3択が提示される現行の`rollItemOffer`の仕組み上、2個とも所持済みになった以降のウェーブでは選択肢が空になる。これは今回の仕様では特に対処せず、今後のロードマップ作業(他の軸のアイテム追加)でプールを拡充していくことで解消する想定とする。

## 6. スコープ外(今回は決めない・実装しない)

- 役ボーナス軸のうち、同スート・同色・同ランクの緩和/強化アイテム → 次回以降
- コンボ軸・全消し軸・詰み救済軸の新規アイテム → `docs/shidasu-roadmap.md`に追記して次回以降
- 「ワンパン軸」(少ない枚数で高得点)という新しい軸の新設 → `docs/shidasu-roadmap.md`に追記して次回以降
- アイテム所持数の上限・入れ替え機能 → `docs/shidasu-roadmap.md`に追記して次回以降
- ワイルドカードを山札に供給する新規アイテムの実装 → 次回以降(3.2節の緩和ルールが実際に機能するために将来必要になる)
- ②秘儀・③天啓・④神託(プレイ中に能動的に使用するアイテム種別)の導入・専用UI

## 7. 受け入れ基準

1. 既存7個のアイテム(紅の目利き・宮廷の紋章・コンボシールド・厚めの山札・ワイルド★・助走・完全消去)が、名前・効果・関連ロジックごとゲームから削除されている
2. 新規2個の護符「架橋の護符」(`bridge`)・「寛容の護符」(`grace`)が`ITEM_POOL`に追加され、ウェーブクリア時の選択肢に出現しうる
3. 全アイテムが1種類につき最大1個までしか選択・保持できない(既に持っているアイテムは次回以降のオファーに出現しない)
4. 架橋の護符を持っていない状態で、階段の成立に最小連続5枚が必要になっている
5. 架橋の護符を持っている状態で、階段の成立に必要な最小連続枚数が3枚に緩和される
6. 寛容の護符を持っていない状態で、列一掃ボーナスは「対象列の全カードを1回も途切れていない連続コンボで0枚にした場合」にのみ加算される
7. 寛容の護符を持っている状態で、列一掃ボーナスの条件が「対象列が現在の連続コンボ開始時点で残り3枚(既定値)以下だった場合」に緩和される
8. フラッシュ・ロイヤルセット・コンプリートランの判定ロジックに、ワイルドが不足分を埋める処理が実装されている(ワイルドカードの供給源が現状存在しないため、実際のプレイでは発動しなくてよい)
9. `npm run test`・`npm run build`が成功する
