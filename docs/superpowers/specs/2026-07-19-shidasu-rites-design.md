# Shidasu 秘儀(Rite)アイテム群 追加 設計

## 0. 背景・目的

`docs/superpowers/specs/2026-07-09-culmen-theme-and-item-motif-design.md`で構想されていたアイテム4分類のうち、②秘儀(Rite)を初めて実装する。

| # | 呼称 | 発動条件 | モチーフ | 個数 |
|---|---|---|---|---|
| ① | 護符(実装済み) | 持っているだけで効果を発揮する | なし(自由命名) | 87 |
| ② | **秘儀(今回)** | **プレイ中に使用することで盤面に効果を発揮する** | **北欧ルーン文字(エルダー・フサルク)** | 24 |
| ③ | 天啓(未実装) | いつでも使用可能、デッキ構成に効果 | 二十八宿 | 28 |
| ④ | 神託(未実装) | いつでも使用可能、役の基礎点を永続強化 | 八卦 | 8 |

秘儀は、護符のような「常時発動のパッシブ効果」とは異なり、プレイヤーがプレイ中の任意のタイミングで能動的に使用する消費アイテムである。

## 1. 基本ルール

- **所持上限**: 最大3個。同じ種類を複数所持することも可能(例: 「ウルズ」を同時に2個所持できる)
- **消費**: 使用すると即座に効果を発揮し、所持から1個削除される(使い切り)
- **取得方法(仮仕様)**: 護符を取得した直後、所持数が3未満であれば、秘儀プール(効果が実装済みの秘儀全種、既に所持している種類も除外しない)から1つを均等ランダムに抽選して追加する。所持数が既に3ならば何も起こらない(取得スキップ)。ゲーム内通貨実装後にショップ購入へ移行する構想があるが、これは本設計のスコープ外(`docs/shidasu-roadmap.md`項目5)
- **持ち越し**: 秘儀の効果はすべてそのウェーブ限りで、次のウェーブには一切持ち越さない(デッキ構成への恒久的な変換は行わない)。ウェーブ開始時(`startWave`)にウェーブ内限定の状態はすべて初期化される

## 2. 命名・モチーフ

②秘儀は、モチーフ設計spec通り「エルダー・フサルク(北欧ルーン文字、全24文字)の個別名をそのまま使用する」方針に従う。

- 表示名は各ルーンの**グリフ文字そのもの**(例: `ᚱ`)を使う。護符のような日本語の意訳名(例:「架橋」)は付けない
- カタカナ読み(例: 「ライドー」)は、管理画面での識別用ラベルとしてのみ使用し、プレイ画面には表示しない
- 全24文字の参照データ(グリフ・カタカナ読み)を新規ファイル`src/lib/game/shidasu/runes.ts`に持つ。今回効果を設計する17文字と、未割り当てのまま将来の追加用に温存する7文字(ハガラズ・ナウジズ・イサ・ソウィロ・ベルカナ・エワズ・マンナズ)の両方を含む、24文字全件を定義する
- **重要**: この`runes.ts`の24文字一覧は、あくまで管理画面の「名前」`<select>`に表示する見た目の選択肢(グリフ・読みの参照データ)に過ぎず、後述の`RiteId`型(内部ID)とは独立している。「どのIDにどのグリフを割り当てるか」は`params.rites`側の`name`フィールドが単独で決める(護符の`id`と`name`が独立しているのと同じ関係)。効果が未設計の7文字も選択肢としては表示されるが、`RiteId`型自体には含めない(詳細は5節)

### 2.1 ルーン文字の表示(Webフォント同梱)

現状このプロジェクトは`src/app.css`にカスタムフォント指定が無く、スート記号(♠♥♦♣)を含めてOS標準のフォールバックフォントに依存している。ルーン文字(Unicode Runicブロック、U+16A0〜)はWindows(Segoe UI Historic)では標準表示できるが、macOS/iOS/Androidでは環境によって表示できない(文字化け)リスクがある。

これを避けるため、Noto Sans Runicなどのオープンフォントから、実際に使用する文字(24文字、将来分含む)のみをサブセット化したWOFF2ファイルを`static/`配下に配置し、`@font-face`で読み込む。文字数が少ないため、ファイルサイズは数KB程度に収まる見込み。これにより環境に依存せず全ユーザーに同じ見た目でルーン文字を表示できる。

## 3. 秘儀候補(17個)と効果テンプレート

`desc`は護符の`desc`(`{x}`等のプレースホルダーを含む言い切り文)と同じ形式。

| ルーン(グリフ・読み) | 効果テンプレート(desc) | 使用条件 |
|---|---|---|
| ᚱ ライドー | 場札のランダムな1列を階段に変換する(最下段起点、昇順/降順はランダム) | 常時使用可 |
| ᛃ イェラ | 場札の各列をそれぞれソートする(列ごとに昇順/降順はランダム) | 常時使用可 |
| ᚹ ウンヨー | 場札を一番多い色に統一変換する(変換後のスートはカードごとにランダム) | 常時使用可 |
| ᛟ オセラ | 場札を一番多いスートに統一変換する | 常時使用可 |
| ᛈ ペルスロ | 現在のチェーンの一番上のカードをワイルドに変換する | 常時使用可 |
| ᚢ ウルズ | 現在のコンボ数に+{n}する | 常時使用可 |
| ᛜ イングズ | 基礎コンボ数に+{n}する | 常時使用可 |
| ᚷ ゲボ | 捨て札からランダムに、場札の各列へ1枚ずつ配置する | 捨て札枚数が列数未満なら使用不可 |
| ᚠ フェフ | 山札の上から、場札の各列へ1枚ずつ配置する | 山札の残りが列数以下なら使用不可 |
| ᛞ ダガズ | 捨て札を山札に加えてシャッフルする | 常時使用可 |
| ᛉ アルギズ | そのウェーブが終わるまで、場札のどの列からでもカードをプレイできるようになる | 常時使用可 |
| ᛏ ティワズ | 現在のチェーンのカードを、チェーン内で一番多いスートに統一変換する | チェーンが2枚以上のときのみ使用可 |
| ᛚ ラグズ | 現在のチェーンのカードを、チェーン内で一番多い色に統一変換する(変換後のスートはカードごとにランダム) | チェーンが2枚以上のときのみ使用可 |
| ᛇ エイワズ | コンボリセットを{n}回防ぐ | 常時使用可 |
| ᚨ アンスズ | 場札の中からランダムに{n}枚をワイルドに変換する | 常時使用可 |
| ᚲ ケナズ | 場札のJ・Q・K以外のカードを、ランダムにJ・Q・Kのいずれかへ変換する(スートは維持) | 常時使用可 |
| ᚦ スリサズ | 場札のJ・Q・Kのカードを、ランダムにJ・Q・K以外のランクへ変換する(スートは維持) | 常時使用可 |

未割り当ての7文字(ハガラズ・ナウジズ・イサ・ソウィロ・ベルカナ・エワズ・マンナズ)は、今回は効果を設計せず`runes.ts`の参照データにのみ存在させる(今後の秘儀追加用)。

### 3.1 「コンボリセットを{n}回防ぐ」の適用範囲

コンボリセットは現在、通常のドロー時リセット(`drawStock`)・全消し(`playCard`)・手詰まり(`applyStuckCheck`)の3経路すべてで共通処理`resetComboFields`を呼ぶ構成になっている(2026-07-19の復活系護符再設計で統一済み)。エイワズの「防ぐ」は、この3経路すべてに対して一律に適用する: `resetComboFields`が呼ばれる直前に残り回数を確認し、1以上あれば「リセットを起こさず現状維持」した上で残り回数を1減らす。全消し・手詰まり自体の判定(全消しボーナス加算・護符解決など)は通常通り行うが、コンボ・チェーンの状態だけがリセットされずに保持される。

## 4. UI

### 4.1 プレイ画面(PlayArea)

- 所持中の秘儀(最大3個、重複あり得る)を、専用のボタン列としてPlayArea内に新設する
- 各ボタンにはルーングリフ文字を表示する(装飾用に前セクションで決定したWebfontを使用)
- クリックで即座に発動・消費する(確認ダイアログなし)
- マウスオーバー時、ネイティブの`title`属性で効果テキスト(`desc`のプレースホルダーを実際の値に置換したもの)を表示する
- 使用条件を満たさない秘儀(捨て札不足・山札不足・チェーン2枚未満など)は、ボタンをdisabledにして誤発動を防ぐ(山札0枚時に山札ボタンをdisabledにする既存の実装パターンを踏襲)

### 4.2 管理画面(`/admin/shidasu-rites`)

`/admin/shidasu-talismans`とほぼ同じテーブル構成の新規ページを追加する。

- 「護符名」相当の列は「名前」列とし、**自由文字入力ではなく`<select>`**にする。選択肢は`runes.ts`の全24文字(グリフ+カタカナ読み、例: `ᚱ ライドー`)。選択済みの状態でもドロップダウンの表示テキストにカタカナ読みがそのまま見えるため、追加のラベル表示は不要
- 「レア度」列は無し(秘儀にレア度の概念はない)
- 「パラメータ」「説明文テンプレート」「プレビュー」列は護符の管理画面と同じ構成

## 5. データ構造

- `src/lib/game/shidasu/types.ts`: 新規`RiteId`型を追加。**今回効果を実装する17種のみ**をメンバーとするunion型とする(例: `'raidho' | 'jera' | 'wunjo' | ...`の17個)。未割り当ての7ルーンは`RiteId`に含めない(効果が実装されて初めて`RiteId`に追加する)
- `src/lib/game/shidasu/runes.ts`(新規): `RiteId`とは独立した、全24ルーンの`{ glyph: string; reading: string }`一覧。管理画面の`<select>`選択肢・読み方ラベルの参照元(見た目のグリフ候補を提供するだけで、`RiteId`との対応関係は持たない)
- `src/lib/game/shidasu/params.ts`: `ShidasuParams`に`rites: Record<RiteId, { name: string; desc: string; ...効果パラメータ }>`を追加(`talismans`と同型構造だが`rarity`フィールドなし)。`RiteId`が17種のみのため、`rites`も17エントリで型が完結し、効果の無いプレースホルダーは不要になる。各エントリの`name`には`runes.ts`の24候補から選んだグリフ文字を設定する(護符の`id`と`name`が独立しているのと同じ関係。将来的に7ルーンのいずれかを新しい`RiteId`に割り当てて追加できる)
- `src/lib/game/shidasu/types.ts`の`RunState`: `rites: RiteId[]`(所持中の秘儀、最大3、重複可)を追加
- `src/lib/game/shidasu/types.ts`の`WaveState`: 秘儀のウェーブ限定永続効果用に以下を追加
  - `comboResetShieldRemaining: number`(エイワズ用、コンボリセットを防ぐ残り回数)
  - `playFromAnywhereActiveThisWave: boolean`(アルギズ用、そのウェーブ中は`isPlayable`判定をバイパスするフラグ)
  - いずれも`startWave`で初期値(0・false)にリセットされる。ウェーブ中に消費・上書きされることはあってもウェーブを跨いで引き継がれることはない
- `src/lib/game/shidasu/riteEffects.ts`(新規): 秘儀ごとの効果ロジックを実装するモジュール。`itemEffects`系のモジュール分割パターンを踏襲し、新しい秘儀を追加する際は「`RiteId`に1メンバー追加→`params.rites`に1エントリ追加(`name`は`runes.ts`の24候補から未使用のグリフを選ぶ)→`riteEffects.ts`に処理を1つ追加」という最小限の変更で済む構成にする
- `src/lib/game/shidasu/engine.ts`: 新規関数`useRite(params, run, riteId, rand) => RunState`。指定した秘儀の効果を`riteEffects.ts`経由で適用した新しい`RunState`を返し、`run.rites`から対象を1個削除する
- 秘儀の取得ロジック: 護符取得確定処理(`pickItem`/`confirmItemSwap`等、既存の護符取得フロー)の直後に、`run.rites.length < 3`なら`RiteId`の全メンバー(=効果実装済みの17種)から均等ランダムに1つ抽選して`run.rites`に追加する処理を挟む

## 6. スコープ外

- ゲーム内通貨・ショップ経由での秘儀購入(`docs/shidasu-roadmap.md`項目5で別途検討)
- 未割り当ての7ルーン(ハガラズ・ナウジズ・イサ・ソウィロ・ベルカナ・エワズ・マンナズ)への具体的な効果の設計・`RiteId`への追加(今回は`runes.ts`の見た目候補としてのみ存在し、実際に秘儀として機能させるのは将来の別タスク)
- ③天啓・④神託の実装
- 護符の並び替えUI(`docs/shidasu-roadmap.md`項目6、既存の未着手課題)

## 7. 受け入れ基準

1. `RiteId`型(効果実装済み17種のみ)・`runes.ts`(見た目用の全24ルーン参照データ、`RiteId`とは独立)・`ShidasuParams.rites`(`RiteId`の17種すべての効果パラメータ)が実装されている
2. 護符取得直後、所持秘儀が3未満なら`RiteId`の17種から均等ランダムに1つ抽選して追加され、3個所持時は取得がスキップされる
3. `useRite`で秘儀を使用すると、対応する効果(17種それぞれ)が正しく盤面に反映され、対象の秘儀が所持から1個削除される
4. ウェーブが切り替わると、秘儀由来の永続効果(コンボリセット防止残り回数・全列プレイ可能フラグ)がリセットされ、次ウェーブに影響しない
5. `PlayArea`に秘儀ボタン列が表示され、クリックで即時発動、マウスオーバーで効果テキストが表示され、条件を満たさない秘儀はボタンがdisabledになる
6. `/admin/shidasu-rites`が新設され、名前列が24ルーンからの選択式になっており、レア度列が無いことを除き護符管理画面と同じ構成で表示・編集・保存ができる
7. ルーン文字用のWebフォントが同梱され、OS標準フォントに依存せずルーン文字が表示される
8. `npm run test`・`npm run check`・`npm run build`が成功する
