# Shidasu 護符管理画面「実際の効果(監査用)」ラベル追加 設計

## 0. 背景・目的

`/admin/shidasu-talismans`は、護符ごとの名前・レア度・パラメータ・説明文テンプレート・プレビュー(実際の数値を埋め込んだ説明文)を編集・確認できる管理画面である。

現状、説明文テンプレート(`desc`)はプレイヤー向けの表示用テキストであり、実装(`engine.ts`・`itemEffects`系モジュール)のロジックとは別に人力で管理されている。護符の効果を再設計・修正した際に、実装だけ変更して説明文の更新を忘れるケースが起こりうる(実際、直近で再生・治癒・不屈の3護符を再設計した際にもこの点が課題として意識された)。

そこで、実装ロジックを開発者向けに要約した「実際の効果(監査用)」ラベルを護符ごとに追加し、説明文と実装の乖離を目視でチェックできるようにする。

## 1. データの持ち方

新規ファイル`src/lib/game/shidasu/itemActualEffects.ts`に、以下の対応表を定義する。

```ts
import type { ItemId } from './types'

export const ITEM_ACTUAL_EFFECTS: Record<ItemId, string> = {
  // ...全87護符ぶん
}
```

`Record<ItemId, string>`型にすることで、TypeScriptのコンパイルチェックにより全87護符ぶんのエントリが漏れなく存在することを保証する(1つでも欠けていれば型エラーになる)。

この対応表は`ShidasuParams`(config)とは完全に独立した、ソースコード内の静的な定数である。管理画面の保存API(`/api/admin/shidasu-config`)を経由した読み書きの対象にはならず、開発者がコードを直接編集することでのみ更新される。これにより、既存の`desc`(説明文テンプレート)の編集・保存フローと混同されることを避ける。

## 2. テキストの書き方

説明文テンプレート・プレビュー列は実際のパラメータ数値を埋め込んだプレイヤー向け文章だが、「実際の効果」列はパラメータキー名(管理画面の「パラメータ」列に表示されているものと同じ記号: `x`・`c`・`p`など)を用いて一般化した、開発者向けの一文で記述する。

例:
- `regeneration`(再生): 「全消し時、山札が1枚以上あればスコアのp%を消費して捨て札から場札を全復活させ、その後山札を1枚めくる(ウェーブ中1回のみ)」
- `courage`: 「コンボ数がc以上のとき、獲得点をx倍にする」

各護符のテキストは、`src/lib/game/shidasu/itemEffects/`配下の各モジュール(`clearBonusEffects.ts`・`cardComboEffects.ts`・`chainAttributeEffects.ts`・`stateAndPatternEffects.ts`)・`directEffects.ts`・`patterns.ts`・`engine.ts`内の特殊処理(再生・治癒・不屈・永劫・豊穣・静寂などwave/runの状態を直接書き換える処理)を実際に読んで、正確な内容にまとめる。

## 3. 表示

`src/routes/admin/shidasu-talismans/+page.svelte`の既存テーブルに、「プレビュー」列の右へ「実際の効果(監査用)」列を追加する。`ITEM_ACTUAL_EFFECTS[id]`の値を読み取り専用テキストとして表示する(入力欄にはしない。他の列のような`bind:value`は使わない)。

## 4. 作成範囲

全87護符ぶんを今回一度に書き起こす。`ITEM_GROUPS`(`src/lib/game/shidasu/itemGroups.ts`)に列挙された18グループ・87護符すべてが対象。

## 5. スコープ外

- 説明文(`desc`)と「実際の効果」列の自動差分検出・不一致ハイライト機能は作らない。人間が2列を見比べて判断する運用とする。
- 「実際の効果」列を管理画面から編集・保存する機能は作らない。更新はソースコードの直接編集でのみ行う。
- `desc`テンプレート自体の内容見直し(今回の対応表作成の過程で乖離が見つかっても、descの修正自体は本タスクのスコープ外とし、別途報告する)。

## 6. 受け入れ基準

1. `src/lib/game/shidasu/itemActualEffects.ts`が全87護符ぶんの`ITEM_ACTUAL_EFFECTS`を持ち、1つでも欠けていればコンパイルエラーになる
2. `/admin/shidasu-talismans`のテーブルに「実際の効果(監査用)」列が追加され、対応する護符の実際の効果テキストが表示される
3. 既存の護符一覧・保存・プレビュー機能(名前・レア度・パラメータ・説明文テンプレートの編集や保存)に変更がない
4. `npm run check`・`npm run build`が成功する
