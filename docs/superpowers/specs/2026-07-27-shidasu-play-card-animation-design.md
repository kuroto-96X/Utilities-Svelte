# 場札プレイ時のカードアニメーション設計

## 背景・目的

星詠みソリティア「Shidasu」の通常プレイ画面(`PlayArea.svelte`)で、場札からカードをプレイした際に演出が一切なく、チェーンへ即座に追加される。プレイの手応えを高めるため、カードが画面上を移動する演出を追加する。

## 要件

- プレイ対象のカードを上方向に画面外まで移動させる(速度x)
- 画面外に完全に出たら、チェーンのカード置き場の右側・画面外の位置へ瞬間移動する
- そこから左方向に移動させ(速度x)、チェーンの実際の追加位置に到達したらアニメーション終了
- アニメーション中はカードクリック・山札めくり・秘儀・天啓の使用など、通常プレイ画面上のすべての操作を実行不可にする

## スコープ

- 対象は通常のプレイ画面(`PlayArea.svelte`経由、`onPlayCard`によるプレイ)のみ
- バラ売り・福袋の中身選択画面(福袋購入後の護符/秘儀/天啓/神託選択UI)は対象外。これらは別コンポーネント・別フローであり、今回のアニメーションは適用しない
- 山札めくり(`onDraw`)自体にはアニメーションを追加しない(チェーンへの追加のみが対象)

## 全体方針

現在、`PlayArea.svelte`の`onPlayCard(colIndex, rowIndex)`が呼ばれると、親(`+page.svelte`)の`handlePlayCard`が即座に`applyPlayCard`を実行し、スコア加算・チェーン追加・自動遷移(ウェーブ目標達成・手詰まり判定など)までが同期的に確定する。

アニメーション追加にあたり、この確定タイミングをアニメーション完了後にずらす。

1. カードクリック時、`applyPlayCard`を即座に呼ばず、まずクリックされたカードの実データはそのまま(場札に残したまま)、見た目だけをオーバーレイで演出する
2. アニメーション完了時点で初めて`applyPlayCard`を実行し、以降は既存ロジック(スコア加算・チェーン追加・自動遷移)がそのまま発生する

こうすることで、目標達成・手詰まり等の自動遷移ロジックには一切手を入れず、実行タイミングが後ろにずれるだけで済む。

## アニメーションの流れ

合計時間は約350ms(上方向150ms + 左方向200ms)。

1. **開始**: クリックされたカード要素の画面座標(`getBoundingClientRect`)を取得し、同じ見た目のカード(`CardFace`)を`position: fixed`のオーバーレイとして同じ位置に表示する。元の場札のカードはこの間非表示にする(実データはまだ場札に残っている)
2. **上方向移動(150ms)**: オーバーレイを画面上端の外側まで、CSS transitionで移動させる
3. **瞬間移動**: 画面外に出た直後、transitionなしでチェーンのカード置き場の右側・画面外相当のX座標(チェーンエリアのY座標、画面右端より外側のX座標)へ座標だけを変更する
4. **左方向移動(200ms)**: チェーンに実際に追加される位置(山札由来のカードと同じく通常は0px、直前のドロー由来なら20pxオフセットのルールを踏襲)へ向けてCSS transitionで移動させる
5. **終了**: 到達したらオーバーレイを破棄し、`applyPlayCard`を実行して実データを反映する。以降のstate更新・再描画は既存の流れと同じ

## 操作ロック

- アニメーション中は`PlayArea.svelte`内の以下をすべて`disabled`にする:
  - 場札のカードクリック(`onPlayCard`のトリガーとなるボタン)
  - 山札めくりボタン(`onDraw`)
  - 秘儀・天啓の使用ボタン
- `+page.svelte`側に`isPlayingCardAnimation`のようなアニメーション中フラグを持たせ、`PlayArea`に新規propとして渡す。既存の`allowDraw`等とは独立したpropとして追加する

## コンポーネント構成

- **`PlayArea.svelte`の変更**:
  - カードクリック時、即座に`onPlayCard`を呼ぶのではなく、クリックされたカード要素の座標とチェーンの到達点座標を算出し、アニメーション開始をトリガーする
  - チェーンの到達点座標(次にカードが追加される位置)は、既存の`chainRows`/`chainCardOffsetX`の計算ロジックから、次に追加される1枚分の位置として算出する
  - アニメーション中フラグを新規propとして受け取り、場札ボタン・山札ボタン・秘儀/天啓ボタンの`disabled`に反映する
- **アニメーション用オーバーレイ**: `PlayArea.svelte`内に新規で追加する(独立コンポーネントに切り出すかは実装時に判断してよい規模)。`CardFace`を使い、`position: fixed`+CSS transitionで移動させる
- **`+page.svelte`の変更**:
  - `handlePlayCard`は即座に`applyPlayCard`を呼ばず、アニメーション開始の指示を`PlayArea`に伝える形に変更する
  - アニメーション完了コールバックを受け取り、その時点で従来の`applyPlayCard` + `afterAction()`を実行する

## 技術的な注意点

- 座標計算に`getBoundingClientRect`を使うため、DOM操作は`onMount`後・クリックイベントハンドラ内で行う
- チェーンエリアが`overflow-x-auto`で横スクロールする可能性があるため、オーバーレイは`position: fixed`で画面(ビューポート)座標ベースにし、スクロール位置に影響されないようにする
- アニメーション中に発生する場札の見た目のちらつきを避けるため、元カードの非表示とオーバーレイの表示切り替えのタイミングを合わせる

## テスト方針

- アニメーション自体(見た目の動き)は自動テストの対象としない(ブラウザでの目視確認)
- `applyPlayCard`の呼び出しタイミングがアニメーション完了後にずれること、アニメーション中は各操作がブロックされることは、可能な範囲でコンポーネントテストまたは手動確認で担保する
